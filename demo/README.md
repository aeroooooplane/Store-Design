# 影石门店 Demo v2

## 真实 SU 接入进度（2026-09-26）

首页下方“真实 SU 道具 · 接入检查”可按需加载首张体验桌，旋转缩放、切换白模/原材质并下载 PNG。需本机存在转换后的 GLB，见 [本地转换说明](public/assets/su/README.md)；缺文件会报错，不以参数化模型冒充。首张约 32.5 MB，SI/正面方向未确认，材质只做初步检查。平面方案仍使用旧参数化道具，尚未自动替换。

本地真实资产专项验证：设置环境变量 REAL_ASSET_QA=1 后运行 `npx.cmd playwright test tests/asset-viewer.spec.js -g "local real asset" --workers=1`。常规测试不依赖未上传的大文件。

## 运行

在本目录执行 `npm.cmd install`、`npm.cmd run dev`，打开终端显示的本地地址。生产构建：`npm.cmd run build`。浏览器验证：`npx.cmd playwright test --workers=1`（测试配置使用本机 Edge）。

## 体验路径

1. 输入宽、深和层高，或输入面积与长宽比，同时选择门店铺型：边厅店（默认）或中岛店。仅输入面积时默认正方形。支持长宽各 4–30m、层高 2.4–6m。
2. 页面中央同时显示四个规则生成的布局卡片，点击放大。
3. 拖动、增加、删除道具；选择后可输入位置、旋转 90°。重叠或越界时禁止确认白膜。通道、消防规则尚未接入。
4. 保存快照或确认平面；系统使用同一米制空间数据创建 Three.js 白膜，可旋转缩放。确认平面和白膜均有独立节点。边厅使用正面开放的剖切墙体；中岛以四周开放演示，不生成外围墙及墙上标识。
5. 默认 SI1.0，可选 SI2.0 或双风格。确认后本机 WebGL 实际渲染 8 张 960×640 PNG；双风格共 16 张，分别保存在分支中。点击图片放大并下载。
6. 点击历史节点恢复布局，继续修改会产生新快照；切换节点前未保存的编辑会自动留存为独立节点。原方案保持不变。

## 数据与边界

- 布局和分支保存在当前浏览器 localStorage（键 `insta-studio-v2`），支持 JSON 导出备份。旧 Demo 没有持久化数据，本版单独使用新键。
- 图片只保留在当前页面内存，刷新后点击对应渲染节点重新生成。没有后端任务队列、云端存储或跨设备同步。
- 当前使用参数化简化道具、示意材质、剖切墙体和固定相对相机位置，是概念级预览，不是已使用真实 SKP 模型的写实门店效果图。可选实验模型基于 11 家历史门店，仅建议体验桌数量，位置仍由规则生成。
- 铺型保存于根节点及后续布局的 room.shopType；刷新、分支、导出均保留。缺少该字段的旧项目按原有边厅表现补齐，不修改道具位置。
- 四方案基于不同位置模板按空间尺寸计算，固定道具尺度；目前铺型影响边界表达和三维围护，尚未分别训练铺型布局策略，中岛也可能有实际背板或柱位，需后续按图纸补充。布局规则不代表施工或消防审核。
- 面积不能还原真实户型；输入真实长宽更准确。不规则户型、柱网、真实门窗及 PDF 打包尚未实现。

## 代码

- `src/layout.js`：米制尺寸校验、四方案和碰撞检测。
- `src/main.jsx`：步骤页面、SVG 编辑器、快照及分支。
- `src/scene.js`：白膜、材质、灯光、八机位、PNG 导出和资源释放。
- `tests/workflow.spec.js`：尺寸边界、面积推算、编辑与持久化、白膜和双风格渲染验证。
