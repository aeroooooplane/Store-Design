# 影石门店 Demo v2

## 真实 SU 接入进度（2026-09-26）

首页下方“真实 SU 道具 · 接入检查”可按需加载首张体验桌，旋转缩放、切换白模/原材质并下载 PNG。编辑器可手动加入真实体验桌、配件柜、柜台和桌椅组合，按原尺寸放置、旋转和保存，三维及多角度渲染等待资产加载成功。需本机存在转换后的 GLB，见 [本地转换说明](public/assets/su/README.md)；缺文件会报错，不以参数化模型冒充。首张约 32.5 MB，SI/正面方向未确认，材质只做初步检查。旧方案参数化道具不自动替换。

本地真实资产专项验证：设置环境变量 REAL_ASSET_QA=1 后运行 `npx.cmd playwright test tests/asset-viewer.spec.js -g "local real asset" --workers=1`。常规测试不依赖未上传的大文件。

## 运行

页面底部“项目工具 → 项目备份 · 导入/导出”可恢复之前导出的浏览器项目：校验后合并为新分支并重建节点编号，不覆盖现有项目，未保存调整会先留一份快照。上限 5 MB / 500 节点 / 每方案 200 道具；图像不包含在 JSON 中，导入后可重新渲染，真实 GLB 仍须在本机准备。存储不足或校验失败不会替换当前项目。导入读取和保存期间暂停操作，请等待完成；成功或失败均会解锁。

效果页新增“下载八视角完整包 ZIP”：当前分支的八张 PNG、布局 JSON、SVG 平面及机位/哈希清单一起下载。不含 GLB、原始 SU 或施工图，双风格分支分别打包；刷新后仍需重渲染再导出。

平面编辑页新增“导出平面 SVG”：包含米制尺寸、编号占地、道具规格及资产编号，适合方案评审；按原尺寸打印为 1:50。重叠/越界会阻止导出。图上入口为矩形示例假设，不含真实墙柱、通道或消防验收，不是施工图。白模和 SI 示意环境现在保留相同标识板/灯条几何。

“导出平面 PNG”从同一布局与 SVG 生成分享图片，包含全部图例和标题；最长边 4096 像素、总量最多 800 万像素。长图会整体缩小，不保证文字在缩略图中可读，也不保证打印比例；精确查看和按比例打印请保留 SVG。导出使用点击时的布局，失败会提示且不下载空白图，不改变已保存方案。

在本目录执行 `npm.cmd install`、`npm.cmd run dev`，打开终端显示的本地地址。生产构建：`npm.cmd run build`。浏览器验证：`npx.cmd playwright test --workers=1`（测试配置使用本机 Edge）。

## 体验路径

1. 输入宽、深和层高，或输入面积与长宽比，同时选择门店铺型：边厅店（默认）或中岛店。仅输入面积时默认正方形。支持长宽各 4–30m、层高 2.4–6m。
2. 页面中央同时显示四个规则生成的布局卡片，点击放大。
3. 拖动、增加、删除道具；选择后可输入位置、旋转 90°。“撤销删除”可恢复当前编辑过程中最近 20 次删除，保留原对象和位置；保存、重新打开方案或刷新后清空此临时记录，不是通用撤销。恢复后仍按当前布局检查重叠/越界，达到 200 件时暂停恢复。重叠或越界时禁止确认白膜。通道、消防规则尚未接入。
4. 保存快照或确认平面；系统使用同一米制空间数据创建 Three.js 白膜，可旋转缩放。确认平面和白膜均有独立节点。边厅使用正面开放的剖切墙体；中岛以四周开放演示，不生成外围墙及墙上标识。
5. 选择 SI1.0/SI2.0 参考环境或对比两种环境（均未验收，不据此判定门店 SI）。确认后本机 WebGL 实际渲染 8 张 960×640 PNG；双环境共 16 张，分别保存在分支中。点击图片放大并下载。
6. 点击历史节点恢复布局，继续修改会产生新快照；切换节点前未保存的编辑会自动留存为独立节点。原方案保持不变。

## 数据与边界

- 布局和分支保存在当前浏览器 localStorage（键 `insta-studio-v2`），支持 JSON 导出备份。旧 Demo 没有持久化数据，本版单独使用新键。
- 图片只保留在当前页面内存，刷新后点击对应渲染节点重新生成。没有后端任务队列、云端存储或跨设备同步。
- 手动加入的四类真实道具使用源 SU 转换网格和原导出材质；自动四方案仍使用参数化道具。配合示意环境、剖切墙体和固定相对机位，是概念级预览，不是已核实整店几何的写实效果图。可选实验模型基于 11 家历史门店，仅建议体验桌数量，位置仍由规则生成。
- 铺型保存于根节点及后续布局的 room.shopType；刷新、分支、导出均保留。缺少该字段的旧项目按原有边厅表现补齐，不修改道具位置。
- 四方案基于不同位置模板按空间尺寸计算，固定道具尺度；目前铺型影响边界表达和三维围护，尚未分别训练铺型布局策略，中岛也可能有实际背板或柱位，需后续按图纸补充。布局规则不代表施工或消防审核。
- 面积不能还原真实户型；输入真实长宽更准确。不规则户型、柱网、真实门窗及 PDF 打包尚未实现。

## 备份、恢复与换电脑

- 修改中的平面草稿会自动保存，刷新可恢复；“导出当前备份”包含草稿，建议重要节点另存 JSON。达到数量/字节上限或存储失败时先导出，不要关闭页面。
- 同时开两个窗口修改同一项目时，较旧窗口会拒绝覆盖并提示冲突。先从冲突窗口导出 JSON，再刷新读取新状态，按需导入合并。不是实时协作。
- 损坏的本地记录不会被自动覆盖：恢复页先下载原始数据，或“隔离备份后新建”。隔离副本仍在浏览器，清除站点数据也会清除它，下载到文件才是独立备份。
- Git 推送不包含浏览器项目、本机 GLB 或原始资料。换电脑需要 JSON 备份及同编号本机资产；不要把代码同步误认为项目自动同步。
- 浏览器存储还按网址来源隔离：`localhost` 与 `127.0.0.1`、5179 开发端口与 5184 预览端口不是同一份项目。平时固定同一地址；切换前先导出 JSON，再在新地址导入，不要直接清除浏览器数据来“找回”。
- 手机窄屏使用“历史与备份”展开侧栏；底部项目工具始终可用。

## 五店证据怎么用

“查看五店案例证据”按 SI 和用途筛选，分别查看平面参考和效果参考。每条保留门店、版本来源、PDF 页码、哈希、证据及冲突；15 条平面、18 张效果不是可直接训练的同机位配对数据，也不会自动生成完整店铺几何。

在开发服务或本机 preview 中，点击“载入本机证据”才读取白名单原件；服务端和页面核对 SHA256 后可打开 PDF/图片。缺件或不匹配明确报错，不用占位图替代。单纯复制 dist 到静态托管没有本机证据服务；本项目目前不部署、不上传原件。

## 验证构建后的网页（仅本机）

在 demo 目录执行以下 PowerShell 命令；需要四个已转换 GLB 和案例引用文件均在原路径。5184 端口须空闲，测试自行启动/结束本机预览服务，使用独立测试浏览器，不覆盖日常浏览器项目。

```powershell
npm.cmd run build
$env:PRODUCTION_QA='1'
npx.cmd playwright test --config playwright.preview.config.js --workers=1
Remove-Item Env:PRODUCTION_QA
```

专项通过真实页面导入四道具布局、下载平面 SVG/PNG、生成白模和八视角 ZIP，核对同一布局及图像哈希，再导出备份、刷新、重新导入验证独立分支；同时校验本机 PDF/效果原图。测试截图在 `output/web-qa/production-*.png`，preview 错误附件独立放在 `demo/.cache/playwright-preview`，不与常规测试报告互相清理。不提交原始资产。默认完整测试跳过这些需要本机大文件的专项。测试环境允许软件 WebGL，结果证明功能闭环，不证明 RTX4070 性能，也不等同写实材质验收。

## 本机演示与交付检查

1. 先在当前浏览器导出已有项目备份，再固定地址启动网页。输入已核对的真实长宽；只有面积时生成的矩形只是推算，不是 PDF 户型还原。
2. 选择一个候选方案，在平面中调整道具。要用真实道具，手动加入对应四类资产；不会把参数化示例自动冒充 SU。误删可立即“撤销删除”，随后保存平面快照。
3. 查看五店证据，核对门店、版本、SI依据与缺件。此入口不替你修改布局；缺证据仍保留未知，不把参考页当完整几何。
4. 处理重叠/越界，分别导出平面 SVG 与 PNG。SVG用于矢量查看，PNG用于分享；两者都不是施工图。尺寸、编号及图例需人工复核。
5. 确认白模，等待真实网格加载完成，拖动检查位置和朝向，再选参考环境生成八视角。真实道具的正面/SI标签仍待确认，当前环境不是已验收的品牌渲染模板。
6. 下载当前分支八视角 ZIP，并另存项目 JSON。ZIP含图像、布局、SVG及机位清单，JSON用于继续编辑；两种文件均不含GLB/原SKP，换机需另行准备本机资产。
7. 验收时比对布局/机位清单与图像；刷新后图片需重渲染。看到任何保存冲突或失败提示，先导出当前备份，再处理问题，不直接关页。

当前可以交付的是人工复核的概念方案与可追溯输出流程；不等于完成不规则户型、墙柱/入口实测、自动PDF转布局或照片级效果图。

## 代码

道具高度超过输入层高（1毫米数值容差）会提示并阻止白模确认及图像/平面导出；旧项目仍可打开、备份和编辑。系统不自动压缩真实模型，也不据此替代吊顶、净高或安装间隙实测。

历史分支支持按名称搜索（忽略大小写和首尾空格），只过滤列表，关系图仍保留全部节点。清空搜索恢复全部列表；搜索不会改写项目或 SI 标签。从结果打开其他方案时，当前未保存调整仍按原规则保留为独立历史节点。窄屏先展开“历史与备份”。

同一场景内重复摆放相同真实资产只加载/解析一次，实例共享静态网格和材质，各自保留位置、旋转、编号；关闭场景统一释放，不留跨场景缓存。目前只用于这四类静态道具，不包含骨骼动画。数量上限 200 是数据校验上限，不是承诺 200 个复杂道具都流畅。

本机性能复测：在 PowerShell 设置 `$env:ASSET_PERF_QA='1'`，执行 `npx.cmd playwright test tests/asset-performance.spec.js --workers=1` 后移除该环境变量。它测量 1/4/4 个体验桌的加载、请求数和显式 GC 后 JS 堆，报告写入 `output/web-qa/asset-performance-*.json`。不覆盖 GPU/原生内存或长时间泄漏，不用单次秒数作为性能保证。

- `src/layout.js`：米制尺寸校验、四方案和碰撞检测。
- `src/main.jsx`：步骤页面、SVG 编辑器、快照及分支。
- `src/scene.js`：白膜、材质、灯光、八机位、PNG 导出和资源释放。
- `tests/workflow.spec.js`：尺寸边界、面积推算、编辑与持久化、白膜和双风格渲染验证。
