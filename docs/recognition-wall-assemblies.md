# 二维内嵌表达与三维贴面规则

用户明确：图纸中灯箱和广告机可以用内嵌实体块表达，三维只需要墙面上的面，以降低负担并快速展示。因此平面标注重叠不推导三维开槽、实体厚度或布尔扣洞。

## 本轮处理

- 接收第三轮整店包，48家均确认，806个物体、76条路径、28条答复完整保留。原物体坐标、入口、签名与确认时间不变；补充说明单独记录为代理解释，不冒充用户构造签核。
- 30处墙体分为22处整体范围、5处已描墙带、3处待分类。保留已有凹口和原图几何；墙体标注先画、无填充，设施后画，选中墙体也不覆盖灯箱与广告机。审核页与离线SVG使用同一规则。
- 34条设施与墙体对应关系：8条有明确平面内嵌依据，26条只明确宿主墙，平面安装方式待核。所有已关联设施采用`display3d: wall-surface`、`cutWall: false`、`solidBody: false`。墙体采用`simplified-wall`且`cutForEmbedded: false`。
- PDF-405按用户原答复将左后设施归为“利旧中岛桌”；利旧只表示来源，未从简略符号补造型号、尺寸或拆件。没有新增待用户问题。

原图中的连续范围可包含灯箱投影；这种二维表达并不要求墙和设备做两套厚实体。既有三维实现`wall-picture.ts`已使用`PlaneGeometry`，`white-scene.ts`的embedded路径调用它并跳过设备GLB。本PR只对齐识别标注与导出规则，没有修改这些共用文件，也没有把48家直接写入业务编辑器。

## 数据与操作

`wallGeometry`记录平面表达、依据、代理状态与简化墙策略；`wallInstallation`记录宿主ID、平面安装方式与三维贴面规则。这两种信息不改变原墙新旧/空实属性，也不决定是否扣面积。设备朝向、墙面位置、标高等仍需独立证据，本轮不批量生成真实三维场景。

```sh
node tools/recognition/whole-store-wall-assemblies.mjs --bundle <上一轮目录> --reviewed <用户审核包.json> --spec <墙体表达依据.json> --out <全新目录>
```

校验输入逐文件指纹、源图/页码/图像身份、宿主墙、安装方式及禁止开洞/厚实体规则。`wallAssemblySourcePack`完整保存本轮用户包，`wallAssemblyLog`逐件保存前后值；与批次一起用于导入隔离。图形审核状态保留，原图解释明确记`agent_interpreted`。

本机缓存只存批次绑定和可变标注，完整历史仍在页面原稿与导出包。真实48家缓存约427KB，防止多轮嵌套源包超过浏览器额度；旧完整缓存仍可读取，错批次/重复门店拒绝。删除宿主墙时仅解除设施关系，设备保留；撤销恢复墙与关联。

外置产物沿用完整目录结构：`整店审核.html`、`整店标注草稿.json`、`本轮原始审核包.json`、`墙体表达依据.json`、逐店像素/米制标注及清单、SVG叠图、评分参照、核验报告和237文件SHA。原图及用户包不随Git提交。
