# RTX 4070 本地训练与混合 PDF 整理

本机核验：Windows、RTX 4070，12282 MiB 显存，驱动 591.86；开始检查时约4608 MiB显存已被其他应用占用。原系统 Python 的 torch=2.9.1+cpu，不能用CUDA训练。独立GPU环境在 tools/training/.venv4070，安装及GPU实测结果另行记录，不能用 nvidia-smi 显示正常代替 torch.cuda.is_available() 验证。

更新：独立环境已完成CUDA张量实测，SI1.0/SI2.0各80步GPU训练与权重重载验证均完成。见 [实际试训结果](rtx4070-pilot-results.md)。下文是数据扩充方案，不表示全部图纸已审核或正式模型已完成。

## 先同步并验证来源

本轮将本地快进到 GitHub 的 0a4e05d。该版本收录361份PDF，而旧目录有418条记录，57份未入库。大文件是否下载成功还需以 corpus-audit-4070/summary.json 和 unavailable-local.json 为准。Git LFS指针不是PDF文件；SHA256与仓库对象一致后才扫描，缺失对象需要在有原件的电脑补传。原来的未完成克隆缺少索引，本轮只用 read-tree HEAD 重建索引，再正常快进；不覆盖本地内容。

实测结果：358份PDF哈希一致，累计12,303页；3份远端LFS对象404。缺失原件说明见 `docs/github-missing-assets.md`。发现1组完全相同文件（成都环球中心、成都环球中心2F），后续必须按同一组划分。

185份文件出现解析器警告，4,335页记录了页级警告；这不等于185份PDF都损坏，其中大量是书签树修复提示。以下3份另有内容流/对象引用错误，应优先人工逐页检查并尝试从原CAD重新导出，不自动修复并当作干净标签：台湾远东新竹Big City中岛（PDF-101）、青岛万象城（PDF-393）、马来西亚Pavilion KL（PDF-418）。具体警告保存在每份SHA256页级索引里。

运行 `python tools/training/audit-corpus.py --scan` 可增量扫描：按文件SHA256缓存，保留原有PDF编号，不随新增文件排序重新编号。对同名新版PDF重新生成页级索引。不会覆盖旧分类总表。

## 每页、每个图块分别处理

1. 先识别门店、文件版本、日期、图号、图种。文件名、图框店名、旧总表冲突时进入待复核，不根据主色直接推断SI1/2。原有六份标签冲突保持排除。
2. 页类别允许多标签：封面、目录、平面、立面、效果图、带标注效果图、机电、节点、材料/文字说明、未知。文本稀少的页必须看图，扫描页再做OCR。关键词只负责召回候选。
3. 混排页保存每个图块的矩形和来源页，不把整页缩成512像素。裁切去图框、页眉、空白和批注。带红色尺寸的效果图优先找无标注版本；找不到就单独保留，不自动修图并当成真实监督数据。
4. 布局数据转成有单位的结构：边界多边形、入口、柱墙障碍、道具类别/尺寸/坐标/朝向和证据。无法确认的字段留空；不从PDF纸张比例、建筑面积或外接矩形硬推尺寸。
5. 风格数据保留真实效果图、铺型、视角、材质描述、源版本、裁切框和审核状态。门头、中岛、店内视角分层抽样；商场背景占比高的图片单独标记。保留宽高比，不能无差别中心裁成正方形。
6. 文件级SHA256去重后，对页面和图块再做近重复检查。同店不同版本、视角、裁切及重复文件都必须落在同一个训练/验证/测试组。先固定店级划分再增强；按SI/铺型分层，留出真正未见过的门店。

## 实际抽查发现

已渲染并查看14个定向样本，逐页结论在 `资源库/99_历史归档/训练实验/corpus-audit-4070/visual-review.json`：

- PDF-039/041 的封面写着“效果图”，关键词会误判成训练图片。
- PDF-045/049 是设计施工说明，正文提及“立面”，并非立面图。
- PDF-044第2页是带红色尺寸和材料引线的效果图，不适合直接训练干净风格。
- PDF-040第2页的图框店名可能与文件名不同，需要核对原件。
- PDF-042第2页及PDF-051第1页是真实家具平面图，可进入尺寸标注队列。

这些样本特意覆盖不同候选类型，不应据此报告整个语料的分类准确率。新页默认 training_eligible=false，只有完成来源、类别、裁切/几何和SI复核后才能加入正式训练。

## 两条训练路线

布局：保留现有11店的“面积→体验桌数量”回归作为基线。新增标注后按店评估数量误差、越界、重叠、通道净宽。数量回归不等于完整平面生成；几何生成应在边界/道具标注成熟后独立训练。

效果：先沿用SD1.5 LoRA做4070试跑，512px、batch1、rank4、BF16、梯度检查点。先验证有限loss、显存峰值、权重更新、保存后重载及相同提示词/种子对照，再扩展到800步实验。12GB总显存不是12GB可用显存，OOM时先降低分辨率/释放非必要显存占用，不强行启用CPU回退并宣称GPU训练。

已有22图仅9家训练店和2家验证店，SI版本仍有噪声；可用于管线试跑，不足以证明正式风格泛化。风格LoRA不能确保尺寸、文字、施工规范或多视角空间一致性。真实SketchUp资产拆分仍是独立工作，当前源模型/本机2020版本的前置问题未解决。

## 已准备的GPU入口

`train-style.py` 新增独立输出目录、数据目录、BF16选项、输入图片哈希校验和显存峰值记录；非空输出目录拒绝覆盖。示例：

```powershell
& tools/training/.venv4070/Scripts/python.exe tools/training/train-style.py --mode gpu --style SI1.0 --steps 80 --precision bf16 --output-dir 资源库/99_历史归档/训练实验/rtx4070-pilot/SI1.0-run01
```

GPU依赖和基模已下载，实际运行使用额外的 `--variant fp16 --revision 451f4fe16113bff5a5d2269ed5ad43b0592e9a14`，完整命令见训练README。不要复用已有实验目录。旧tiny模型权重不能用于SD1.5。

所有PDF检查和训练都在本机；网络用于下载依赖、公开基础模型和用户指定GitHub仓库，不上传门店资料。
