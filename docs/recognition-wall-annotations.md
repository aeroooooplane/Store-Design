# 墙体、包柱与增补审核

离线整店标注增加“包墙/包柱”类别。墙体属性在物体的 `wallProperties` 中保存：

| 字段          | 值                                    | 用途                                   |
| ------------- | ------------------------------------- | -------------------------------------- |
| phase         | existing / added / unknown            | 原有、后加、待定                       |
| solidity      | solid / hollow / unknown              | 实心、空心、待定；不代表承重或具体材料 |
| role          | core / cladding / partition / unknown | 核心、外包、隔墙、待定                 |
| wrapsObjectId | 核心物体编号或 null                   | 包覆关系，禁止自指或引用不存在的核心   |
| evidence      | 原图或人工依据                        | 非待定判断必须有依据                   |

包层记录外包轮廓，墙柱核心保留独立轮廓；二者重叠是有意的层级关系，不能简单相加扣面积。按已确认规则，原柱/管井核心扣面积，后加构件只避让；空心与实心不直接决定扣面积。空腔厚度与截面无来源时不补造，当前尚不支持独立空腔多边形或承重判断。

面积提示只描述规则，不计算几何并集，也未接入业务面积或规划器。新旧及作用不明时保持待定。删除被包覆的核心前须解除关联。修改属性可撤销，确认后回列表。

## 增补输入与输出

```sh
node tools/recognition/whole-store-supplement.mjs --bundle <已接续审核包的目录> --supplement <增补依据.json> --out <新目录>
```

增补文件含 `schemaVersion:1`、`reviewSha256` 和 `stores:[{id,objects,questions}]`。只允许增加物体和问题，不覆盖既有物体编号。输入文件逐项核验 SHA；新目录保存原整店审核包和增补依据，生成新的构建数据、逐店 JSON、叠图、审核 HTML、入口参照、核验报告和文件指纹。

`priorWholeReviewPack` 在增补导出中保留前轮原记录；`supplementBatch` 隔离不同批次缓存及导入。只有发生增补的门店重新待审，原答复、原物体与入口坐标逐字段保留。修改前后的确认记录不能混成一次签核。
