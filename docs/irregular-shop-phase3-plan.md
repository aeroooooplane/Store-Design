# 异形店第三阶段：识别（方案，2026-10-16）

接 [异形店支持方案](irregular-shop-plan.md) 第 4 节第 9、10 项。用户 10-16 同意开工，并定下两条原则：

- **识别硬性不使用外部大模型**，图纸不发给任何外部服务；
- **长期目标**：全部图纸清洗完、训练出自己的模型后，识别正确率达到 95% 以上。

本文给出识别模块的现状、纯本地识别的做法、分批计划、通往 95% 的路线、决议和新问题。分工：图纸窗口负责金标准、全量结构化、离线评估和训练；本窗口负责工作台识别模块和模型接入。

## 1. 现状

### 1.1 做法

| 环节 | 现在怎么做 | 对异形店的影响 |
|---|---|---|
| 读图纸 | 浏览器用 pdf.js 读矢量 PDF 的文字、直线、矩形和颜色；**斜线和曲线直接丢弃** | 斜墙、弧墙在第一步就没了 |
| 本地推断边界 | 只找横平竖直的线，拼成矩形或“三边闭合 + 一边开口”的矩形；装不下多数道具就判为异形店，返回空 | 异形店一律识别失败 |
| 比例 | 尺寸文字、带尺寸的道具名、店铺面积、用户两点校准，两种以上读数一致才算可信 | 文字被转成曲线时读不到 |
| 失败后 | 设置了兜底模型就改用视觉模型（通义千问 Qwen3-VL 等） | 异形店全部依赖外部模型 |
| 用户补画 | 识别不出边界时，在空间编辑器里**逐点输入毫米坐标** | 不能在原图上点，异形店补画很费劲 |
| 图片和扫描件 | 本地读不出任何内容，只能交给视觉模型 | 不联网就无法识别 |

### 1.2 图纸构成（图纸窗口按 511 家主平面页统计）

| 类型 | 家数 | 占比 |
|---|---|---|
| 矢量 PDF，有文字层 | 371 | 73% |
| 矢量 PDF，文字已转成曲线（几何还在，尺寸数字要靠 OCR） | 114 | 22% |
| 图片或扫描件 | 19 | 4% |
| 没有平面 | 7 | 1% |

### 1.3 现有本地识别的得分（图纸窗口用 15 家金标准打分，都是有文字层的矢量页）

- 3 家失败，都是边界不闭合：圆形和弓形店。
- 其余 12 家里，比例误差小于 1% 的有 9 家；另 3 家错了 +30%、+57%、+349%，都是**按道具名称框推比例时认错了框**。
- 边界重合度（IoU）中位数约 0.72，达到 0.8 的只有 5 家，主要缺斜边、凹口和包墙。
- 道具位置命中 77/163（47%），型号对上 29/84（35%）。灯箱、LOGO 常被配成“徕卡墙画面”，SI1.0 边桌的正面也会配错。

## 2. 纯本地识别怎么做

| 图纸类型 | 占比 | 本地做法 |
|---|---|---|
| 矢量 PDF，有文字层 | 73% | 矢量识别扩展到多边形和弧线；比例以尺寸链为主 |
| 矢量 PDF，文字转成曲线 | 22% | 边界照样从矢量线拼；尺寸数字和道具名用本地 OCR 读（RapidOCR 同款 ONNX 模型，纯 CPU，图纸窗口实测每页 4–13 秒）；读不出时用两点校准 |
| 图片或扫描件 | 4% | 在原图上描点画边界，用 OCR 或两点校准定比例；**道具由用户自己摆放**（用户已同意） |

整个方案只需要 Node 和浏览器，**不需要 Python，也不需要显卡**。本地视觉模型现在不做，以后由第 4 节训练的自有模型替代。

## 3. 分批计划（每批一个 PR）

1. **原图描点**（所有图纸都能用）：
   - 在识别页的原图上点选顶点围出边界，双击闭合；可以拖动、插入、删除顶点；
   - 矢量 PDF 上，点击会吸附到最近的墙线端点或交点；
   - 圆弧工具：点弧的起点、中点、终点，自动按每段约 15° 离散成折线；
   - 用两点校准定比例（现有工具），换算成毫米后进入空间编辑器核对；
   - 入口、开放边也可以在图上点选边段来设置。
2. **本地矢量识别：边界和比例**：
   - 保留斜线和曲线，曲线离散成折线；
   - 边界优先找租赁线（按颜色、虚线），再从墙线重建闭合多边形，包括直角凹凸、斜墙、圆形和弓形；偏差 3° 以内的墙按直墙处理；
   - 比例以尺寸链为主，店铺面积和两点校准为辅，道具名称框只作佐证；
   - 用金标准回归，指标为边界重合度和比例误差。
3. **本地 OCR**（针对文字转曲线的 22%，以及图片和扫描件的尺寸数字）：
   - 在服务端用 onnxruntime-node 运行 PaddleOCR 的 ONNX 模型（与图纸窗口的 RapidOCR 相同），读尺寸数字和道具名，接入现有的比例和道具推断；
   - 识别耗时几秒，界面显示进度，结果缓存；
   - 模型文件通过 npm 依赖安装，不提交进仓库（LFS 配额已满）。
4. **道具对应改进**：灯箱、LOGO 不再误配成“徕卡墙画面”，SI1.0 边桌朝向按图上的正面判断；用金标准的道具命中率、型号对应率回归。
5. **关闭外部模型**：识别默认完全不调用外部大模型（处理方式见第 6 节新问题）；本地失败时提示用户在原图上描点修正。

第 1 批对所有图纸都有用，先做；第 2、3、4 批相互独立，可以并行；第 5 批很小，随第 1 批一起做。

## 4. 通往 95% 的路线（与图纸窗口共同制定）

### 4.1 怎么算 95%

- **三个数据集**：
  - 测试集：金标准 45 家，只用于最终验收，永远不参与训练，也不用来调规则或挑模型，否则 95% 会被调虚；
  - 开发集：从阶段 3b 抽审过的门店里固定拿 40–50 家，调规则和挑模型只看开发集；
  - 训练集：其余门店和自动生成的数据。同一家店的多页不跨集合。
- **一家店“识别合格”要同时满足**：
  - 比例误差 ≤ 2%（金标准的人工比例误差在 0.4% 以内；2% 相当于 1.8 米的桌子差 36 毫米，不影响使用）；
  - 边界重合度（IoU）≥ 0.90；
  - 主入口所在的边正确（入口错了，排布就全错）；
  - 道具位置命中 ≥ 90%（0.6 米以内一对一匹配）；
  - 型号对应 ≥ 90%。
- **目标按图纸类型分别设**：矢量页（带文字和文字转曲线两类）合格率 ≥ 97%；图片和扫描件单列，先定 ≥ 80%，有了训练模型再提高；同时报告整体合格率。原因是一个算术事实：图片和扫描件占 4%，如果它们只能半自动处理、不计入合格，整体最高只有 96%，所以“整体 95%”只有在矢量页几乎全对时才可能达到。
- **打分脚本**：tools/store-archive/score_drafts.py 由图纸窗口补上“合格”判定和按图纸类型的汇总，同时能给规则结果和模型推理结果打分。每个识别 PR 都附开发集的前后分数，金标准只在阶段验收时打。

### 4.2 四步路线

| 步骤 | 内容 | 负责 | 产出 |
|---|---|---|---|
| 1. 规则先行 | 第 3 节的分批计划：尺寸链定比例、租赁线和墙线拼多边形和弧线、本地 OCR、道具对应。预计矢量带文字的页能做到七八成合格，单靠规则很难到 95% | 本窗口 | 每个 PR 附金标准分数 |
| 2. 自动生成训练数据 | 训练数据的主要来源是**从矢量页自动生成的标注**，不靠人工逐家修正：371 家矢量带文字的页，墙、租赁线（红色虚线）、门、柱、道具框、文字的位置和内容都是精确的，渲染成图片就能直接得到像素级标注。再做增强：去掉文字层模拟“文字转曲线”，加噪声、模糊、倾斜、降分辨率模拟扫描件。这样训练量能做到几千张。人工修正的 plan.json 用来补语义标注，例如哪条是开放边、哪个框对应哪个型号、正面朝哪边 | 图纸窗口，在本机 CPU 上运行 | 数据集和格式说明 |
| 3. 训练 | 在有显卡的电脑上，由用户或 DeepSeek / GPT 的代理按 README 执行，不依赖 Claude，全部用 PyTorch 并避开 AGPL 许可：① 墙、租赁线、门、柱的分割，用 segmentation_models_pytorch（MIT）的 U-Net 或 LinkNet，编码器为 ResNet18 或 MobileNetV3，CPU 推理一页约 1 秒；② 道具检测，用 YOLOX-s 或 tiny（Apache-2.0），角度不靠模型预测，检测出框后用矢量线或边缘做后处理来定；备选 torchvision 的 RetinaNet（BSD）；③ 道具图例分类，用 timm 的 MobileNetV3（Apache-2.0）；④ OCR 识别微调，用 PaddleOCR 的 PP-OCRv4（Apache-2.0），paddle2onnx 导出，与 RapidOCR 格式相同，显卡电脑上要装 PaddlePaddle。不用 Ultralytics YOLO（AGPL） | 图纸窗口写脚本；用户或代理在显卡电脑上运行 | ONNX 模型文件加指标 JSON |
| 4. 接入 | 在 Node 里用 onnxruntime-node 跑 CPU 推理，后处理成空间和布局数据；模型结果与规则结果交叉核对，两者不一致时提示用户在原图上点选或两点校准 | 本窗口 | 金标准测试集达到 95% 合格 |

步骤 1 和步骤 2 可以并行。训练脚本等规则版第一批合并后再写，以沿用相同的后处理口径。在达到目标之前，扫描件仍以原图描点为主。

**阶段 3b 全量结构化**（给开发集和训练集补语义标注）不要求 511 家逐家人工修正：规则版第一批合并后，图纸窗口用它对 511 家全量自动跑，同时自动核对——两种以上比例读数一致、边界面积与图注相差 ≤ 5%、边界闭合、有物料清单的店道具数量对得上。核对通过的直接作为“银标准”，没通过的才人工修正（按现在的草稿质量估计三到四成要修，规则改好后会更少）；用户每 50 家抽审 5 家。工期：自动跑和核对约 1 天，人工修正按每天 30–50 家算约 1–2 周。

### 4.3 交付物（图纸窗口）

- 目录 tools/recognition-training/：export_dataset.py（渲染图片、生成标注、做增强）、train_*.py、export_onnx.py、eval.py、requirements.txt、配置文件、一条命令跑完的入口，以及中文 README，从拷数据、装环境到训练和导出一步步写清，不依赖 Claude。
- 数据集和模型文件不进 Git（LFS 配额已满），存放位置见第 6.2 节的问题。

## 5. 风险

- **矢量线不等于墙**：图纸上还有尺寸线、轴线、图框和家具线。异形店比矩形更容易认错，所以识别结果要叠加在原图上，由用户确认，认错了直接在图上改顶点（第 1 批）。
- **OCR 速度**：每页 4–13 秒，适合上传后后台识别，不适合每改一下就重跑；结果要缓存。
- **OCR 准确率**：竖排和小字号的数字会丢，所以比例仍要求两种以上读数一致才算可信，不可信时提示用户两点校准。
- **训练数据与真实图纸的差距**：自动生成的数据来自矢量页，模拟出的扫描件和真实扫描件不完全一样；所以测试集里要有真实的转曲页和扫描件，三类分开报分。
- **跨机器运行**：训练电脑上不能用 Claude，所以脚本和说明必须自成一体，不依赖本仓库的其他工具；每次交回结果都附环境信息和日志，方便核对。
- **部署环境**：onnxruntime-node 需要服务器的操作系统和 CPU 有对应的预编译包（Windows、Linux x64、macOS 都有）。

## 6. 决议与新问题

### 6.1 决议（2026-10-16）

1. S1 选 A：原图描点做完整版，包括自动吸附墙线、圆弧工具、两点校准，入口也在图上点选。
2. S2 选 A：本地识别斜墙、圆形和弓形。
3. S3 选 A：接入本地 OCR。
4. S4：图片和扫描件只做本地描点加 OCR 或两点校准，**不保留云端大模型**；道具由用户摆放（R2 选 A）。
5. S5 选 B：**默认完全不调用外部大模型**（硬性要求）。
6. S6 选 A：比例以尺寸链为主。
7. S7：用户这台电脑没有独立显卡；另一台有显卡，但只能用 DeepSeek 和 GPT。按第 4 节，训练脚本要能在那台电脑上独立运行。
8. R4 选 A：本地视觉模型现在不做，改走第 4 节的自有模型路线。

### 6.2 新问题（未回答的按推荐执行）

1. **现有的云端视觉识别（通义千问 Qwen3-VL、Claude）怎么处理**
   - **A（推荐）**：从识别功能里移除，包括设置页里识别模型的选项、本地失败后转模型的逻辑，以及识别专用的提示词代码。代码在 Git 历史里可以找回。这样最符合“硬性不用”，也不会被误开。设计助理用的模型不受影响。
   - B：保留代码，作为默认关闭的开关，只能在设置页手动打开，打开时明确提示“图纸会发给外部服务”。
2. **95% 的算法**
   - **A（推荐）**：按第 4.1 节：一家店同时满足比例误差 ≤ 2%、边界重合度 ≥ 0.90、主入口所在的边正确、道具位置命中 ≥ 90%、型号对应 ≥ 90% 才算合格；矢量页合格率 ≥ 97%，图片和扫描件先定 ≥ 80%，同时报告整体合格率。
   - B：整体合格率 ≥ 95% 作为唯一目标（图片和扫描件必须也达到很高的自动合格率才可能实现）。
3. **训练数据集（预计几 GB）和模型文件（每个几 MB 到几十 MB）放在哪里**
   - **A（推荐）**：两台电脑之间用网盘或 U 盘拷贝数据集；训练好的模型文件放进资源库目录，但不进 Git，另外上传到 GitHub Release 供部署下载。
   - B：都放到网盘，由部署脚本下载。
4. **显卡电脑的显卡型号和显存**（请告诉我们）：推荐显存 8 GB 以上；不够的话改用更小的模型。
5. **上线顺序**
   - **A（推荐）**：规则版先上线，覆盖大部分矢量图纸；模型版用来冲 95% 和处理扫描件，训练完成后再接入。
   - B：等模型版达到 95% 后一起上线。
