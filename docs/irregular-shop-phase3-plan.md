# 异形店第三阶段：识别（方案草案，2026-10-16）

接 [异形店支持方案](irregular-shop-plan.md) 第 4 节第 9、10 项。用户 10-16 同意开工，同时提出一个问题：**以后上传图纸识别，能不能完全不依赖外部大模型，在本地电脑上完成？** 本文给出识别模块的现状、能否纯本地识别的结论、分批计划和待确认的问题，**确认后再动手**。分工已与图纸窗口商定：图纸窗口负责金标准 45 家、离线评估、打分脚本和 OCR 评估；本窗口负责工作台识别模块。

## 1. 现状

### 1.1 做法

| 环节 | 现在怎么做 | 对异形店的影响 |
|---|---|---|
| 读图纸 | 浏览器用 pdf.js 读矢量 PDF 的文字、直线、矩形和颜色；**斜线和曲线直接丢弃** | 斜墙、弧墙在第一步就没了 |
| 本地推断边界 | 只找横平竖直的线，拼成矩形或“三边闭合 + 一边开口”的矩形；装不下多数道具就判为异形店，返回空 | 异形店一律识别失败 |
| 比例 | 尺寸文字、带尺寸的道具名、店铺面积、用户两点校准，两种以上读数一致才算可信 | 文字被转成曲线时读不到 |
| 失败后 | 设置了兜底模型就改用视觉模型（通义千问 Qwen3-VL 等） | 异形店全部依赖外部模型 |
| 视觉模型 | 输出多边形边界（3–100 个点），提示词没有说明斜墙、弧线怎么画 | 弧墙质量看运气 |
| 用户补画 | 识别不出边界时，在空间编辑器里**逐点输入毫米坐标** | 不能在原图上点，异形店补画很费劲 |
| 图片和扫描件 | 本地读不出任何内容，只能交给视觉模型 | 不联网就无法识别 |

### 1.2 图纸构成（图纸窗口按 511 家主平面页统计）

| 类型 | 家数 | 占比 |
|---|---|---|
| 矢量 PDF，有文字层 | 371 | 73% |
| 矢量 PDF，文字已转成曲线（几何还在，尺寸数字要靠 OCR） | 114 | 22% |
| 图片或扫描件 | 19 | 4% |
| 没有平面 | 7 | 1% |

### 1.3 现有本地识别的得分（图纸窗口用 15 家金标准打分，都是有文字层的矢量页）

- 3 家失败，都是边界不闭合：圆形和弓形店。
- 其余 12 家里，比例误差小于 1% 的有 9 家；另 3 家错了 +30%、+57%、+349%，都是**按道具名称框推比例时认错了框**。
- 边界重合度（IoU）中位数约 0.72，达到 0.8 的只有 5 家，主要缺斜边、凹口和包墙。
- 道具位置命中 77/163（47%），型号对上 29/84（35%）。灯箱、LOGO 常被配成“徕卡墙画面”，SI1.0 边桌的正面也会配错。

## 2. 能不能完全不用外部大模型

| 图纸类型 | 占比 | 能否纯本地 | 本地方案 |
|---|---|---|---|
| 矢量 PDF，有文字层 | 73% | **能** | 现有矢量识别，扩展到多边形和弧线；比例改为以尺寸链为主 |
| 矢量 PDF，文字转成曲线 | 22% | **能** | 边界照样从矢量线拼；尺寸数字和道具名用本地 OCR 读（RapidOCR 同款 ONNX 模型，纯 CPU，图纸窗口实测每页 4–13 秒，能读出文字层词语的 60–80%，尺寸数字大多能读出）；读不出时用两点校准 |
| 图片或扫描件 | 4% | **半自动能** | 在原图上点选顶点描边界，用 OCR 读尺寸或两点校准定比例；道具在图上框选后对应模型 |
| 扫描件全自动 | — | 有条件 | 本地视觉模型（如 Qwen2.5-VL，用 ollama 或 llama.cpp 运行），需要有显卡的机器；图纸窗口的电脑只有核显，没跑过，暂不建议 |

**结论**：约 95% 的图纸（矢量 PDF）可以做到完全本地识别；剩下 4% 的图片和扫描件用“原图描点 + OCR 或两点校准”也能在本地完成，只是要人点几下。整个方案只需要 Node 和浏览器，**不需要 Python，也不需要显卡**。外部大模型保留为可选项。另外，45 家金标准够用来调规则和做回归，不够训练模型。

## 3. 推荐路线（分批，每批一个 PR）

1. **原图描点**（所有图纸都能用，不需要模型）：
   - 在识别页的原图上点选顶点围出边界，双击闭合；可以拖动、插入、删除顶点；
   - 矢量 PDF 上，点击会吸附到最近的墙线端点或交点；
   - 圆弧工具：点弧的起点、中点、终点，自动按每段约 15° 离散成折线；
   - 用两点校准定比例（现有工具），换算成毫米后进入空间编辑器核对；
   - 入口、开放边也可以在图上点选边段来设置。
2. **本地矢量识别：边界和比例**：
   - 保留斜线和曲线，曲线离散成折线；
   - 边界优先找租赁线（按颜色、虚线），再从墙线重建闭合多边形，不再只限矩形，包括直角凹凸、斜墙、圆形和弓形；偏差 3° 以内的墙按直墙处理；
   - 比例改为**以尺寸链为主**，道具名称框只作佐证，不再单独决定比例（金标准里 3 家比例大错都来自这里）；
   - 用金标准回归，指标为边界重合度和比例误差。
3. **本地 OCR**（针对文字转曲线的 22%）：
   - 在服务端用 onnxruntime-node 运行 PaddleOCR 的 ONNX 模型（与图纸窗口的 RapidOCR 相同），读尺寸数字和道具名，接入现有的比例和道具推断；
   - 识别耗时几秒，界面显示进度；
   - 模型文件通过 npm 依赖安装，不提交进仓库（LFS 配额已满）。
4. **道具对应改进**：灯箱、LOGO 不再误配成“徕卡墙画面”，SI1.0 边桌朝向按图上的正面判断；用金标准的道具命中率、型号对应率回归。
5. **视觉模型提示词补斜墙和弧墙**：斜墙按端点给出，弧墙按每段约 15° 离散，入口可以跨多段边。只在用户选择了模型时生效。
6. **本地视觉模型**：暂不做。等确认部署机器有显卡后再评估。

第 1 批对所有图纸都有用，建议先做；第 2、3、4 批相互独立，可以并行；第 5 批很小，可以随第 2 批一起做。

## 4. 风险

- **矢量线不等于墙**：图纸上还有尺寸线、轴线、图框和家具线。异形店比矩形更容易认错，所以识别结果要叠加在原图上，由用户确认，认错了可以直接在图上改顶点（第 1 批）。
- **OCR 速度**：每页 4–13 秒，适合上传后后台识别，不适合每改一下就重跑；结果要缓存。
- **OCR 准确率**：竖排和小字号的数字会丢，所以比例仍要求两种以上读数一致才算可信，不可信时提示用户两点校准。
- **部署环境**：方案只依赖 Node，但 onnxruntime-node 需要服务器的操作系统和 CPU 有对应的预编译包（Windows、Linux x64、macOS 都有）。

## 5. 分工（已与图纸窗口商定）

- **图纸窗口**：金标准 45 家，其中已审核的异形店有 PDF-293 澳门（弓形）、NEW-095 韩国东滩（正圆）、NEW-088 西安赛高（两个 R2000 圆角）、PDF-088 南昌武商（斜门头加绕柱凹口）、PDF-148 广州万菱汇（三折斜门头、45° 斜墙、绕三根柱）、PDF-186 新乡大桥（斜墙）、NEW-093 长春（直角凹凸），另有 PDF-043、PDF-239、PDF-001 在第 4 批；负责离线评估、打分脚本（tools/store-archive/score_drafts.py）和 OCR 评估。
- **本窗口**：工作台识别模块的原图描点、本地矢量识别、本地 OCR 接入、道具对应改进、视觉模型提示词，以及每批 PR 用打分脚本附上前后分数。金标准第 4 批审核后，把测试里的 5 家草稿边界换成金标准。

## 6. 需要确认的问题（未回答的按推荐执行）

1. **原图描点的交互**
   - **A（推荐）**：点选顶点围成边界，矢量 PDF 上自动吸附到墙线；带圆弧工具（三点定弧）和两点校准；入口和开放边也在图上点选。
   - B：只做点选顶点和两点校准，圆弧和吸附以后再说。
2. **本地矢量识别做到哪一步**（原决议是“本地只做直角凹凸，斜墙和弧墙交给模型”）
   - **A（推荐）**：既然要尽量不依赖外部模型，本地也识别斜墙、圆形和弓形，因为矢量 PDF 里本来就有这些线；识别不准时用原图描点修正。
   - B：按原决议，本地只做直角凹凸。
3. **文字转成曲线的页面（占 22%）**
   - **A（推荐）**：接入本地 OCR（服务端 Node 运行，不需要 Python），读尺寸数字和道具名；读不出时提示两点校准。
   - B：不接 OCR，这类页面只靠两点校准定比例，道具要人工对应。
4. **图片和扫描件（占 4%）**
   - **A（推荐）**：本地走原图描点，加 OCR 或两点校准；云端视觉模型作为可选项保留。
   - B：部署本地视觉模型实现全自动，需要有显卡的服务器。
5. **默认识别方式**
   - **A（推荐）**：本地优先；本地失败时由用户选择在原图上描点修正，或交给模型。设置里增加“不使用外部模型”开关，打开后不会把图纸发给任何外部服务。
   - B：默认完全不使用外部模型，模型入口隐藏。
   - C：保持现状，本地失败自动交给模型。
6. **比例的来源**
   - **A（推荐）**：以尺寸链为主，店铺面积和两点校准为辅，道具名称框只作佐证。
   - B：保持现状，各来源同等对待。
7. **部署环境**（请告诉我们实际情况，方案不依赖它）
   - 部署服务器和你的电脑有没有独立显卡？能否安装 Python？如果都没有，按本方案（只用 Node 和 CPU）做。
