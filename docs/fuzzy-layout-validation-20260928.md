# 标准中岛桌比例布局：实现与验证

## 本轮范围

按用户2026-09-28要求，只考虑明确使用标准长中岛桌的门店。当前工作定义为原平面标注1.8m长桌；0.8m与1.0m深分别保存，未标注深度留空。这个定义是当前样本范围，不是品牌标准认证。异形场地只要有标准桌仍可作参考。

逐张复看首批12张完整平面：10张进入推荐，机场T3的2.6m桌排除；PDF-239文件名沈阳、图签深圳，身份冲突隔离。旧标签、原PDF、图像和旧试训模型均未覆盖。新增观察在 `demo/src/layout-cases.js`，来源页及原文件哈希可通过原manifest和审计结果追溯。

不启动训练。以桌长倍数表示店铺宽深包络，保存约±10%的启发式区间；它不是实测误差保证。桌数只数体验桌，不含收银、开箱、配件边桌。

## 已接入的工作流

新建页面点击“按桌长估比例” → 输入宽、深约几张桌长 → 选择铺型及粗略障碍区域 → 生成四个候选 → 查看案例依据 → 编辑、保存、三维和导出。

原米制输入路径保留，不改旧项目。新路径通过标准桌比例与铺型检索三个近似案例，给数量区间；整组串列/并列/双列摆放，不再使用随机网格散点。侧服务案例会保留侧边服务关系。全部实例使用本机真实1.8×1.0m SU资产，不为凑数拉伸模型，所以0.8m深原案例未必能一比一复刻。

障碍选择是用户的粗略假设：22%店宽×30%纵深的占位块，非识别出的柱子或真实不规则边界。入口、其他服务区也仍有假设。柜体不可放下、零张体验桌的候选会提示不适用并禁用，不宣称通过布局验收。四个候选可以重复，名称中的“相似案例”不代表设计优选。

页面、编辑页和SVG/PNG导出保留“比例估算/案例启发/非实测”说明。导入时检查案例结构与间距记录，原始方案保持。

## 探索性留一验证

执行：在demo运行 `node scripts/validate-fuzzy-layout.mjs`。

每次在检索前排除当前店，只用其粗略宽深比例、铺型和是否受障碍影响预测；不读取该店桌数作为预测输入。身份冲突和非标准桌始终排除。

| 指标 | 结果 | 解读 |
|---|---:|---|
| 标准桌可用案例 | 10 | 不是大规模训练集 |
| 桌数点预测完全一致 | 5/10 | 不足自动定稿 |
| 桌数相差不超过1张 | 10/10 | 可作初筛 |
| 建议区间覆盖 | 10/10 | 区间平均宽度2张，覆盖高不等于准确率100% |
| 平均绝对桌数误差 | 0.5张 | 原面积公式为1.1张；基线使用同一粗略包络折算面积，不是实测面积 |
| 排布类型完全一致 | 1/10 | 不支持“自动选最佳排法”的结论 |
| 宽深各±10%扰动 | 90/90区间覆盖 | 不代表桌数或类型在扰动下不变 |

这是看过全批图纸后设计的探索性留一检查，不是盲测，也没有独立新门店测试集。空间特征和排布标签为人工粗读；尤其不能用点预测/区间结果替代实际布局可用性。

## 结论与下一步

这次完成的是一个可解释、可验证的比例辅助候选生成器，不是可靠的自动设计师。数量初筛比旧面积公式更有依据，但自动类型选择明显不够。应先继续收集标准桌门店的入口/开放边、侧仓和服务位置特征，再用未参与当前设计的新案例验证；在此之前保留人工比较，不能把1/10类型匹配称为达标。
