# 面积自适应布局与材质渲染改造

问题：旧默认四模板在16–225㎡都只放1/1/2/1张桌；所谓风格渲染主要是参数化模型换灰色。本轮以这两个缺口为范围实施。

## 新行为

- 默认按面积给出桌数目标，再用真实模型占地、入口1.2m、主通道1.2m、体验桌与其他道具0.9m间距筛选位置。空间不足自动减量。面积建议为暂定设计规则，非品牌标准或训练结论。
- 四方案为中轴、宽松、纵向、侧向布置；小空间可能得出相同数量，大空间数量继续增长。默认方案 A 在16/36/100/225㎡分别为1/2/5/12张体验桌。
- 默认使用已有三个真实资产编号：体验桌408124、配件柜323015、柜台752992；原尺寸和90°旋转，不能拉伸。配件柜总高约2.4m，过低空间不放入。
- 原来11店实验模型保持可选，超出训练范围时回退到新容量规划，不回退固定模板。新旧浏览器项目保留，旧方案不会自动改几何。
- 平面显示数量、道具尺寸、入口与主通道；SVG/PNG导出保留通道提示和数量。移动道具后若侵占通道或体验区间距不足，阻止确认输出。
- 效果图使用真实SU材质和产品贴图、地砖表面纹理、环境反射、灯轨、背墙格栅和环境遮蔽。新增场景构件在白模和材质图中保持相同几何；不改变原道具网格。
- 第八机位改为1.65m左右的人眼高度；其余保留全景、俯视和角部视角。所有机位从同一场景出图，导出记录实际相机。
- 三维预览改为操作时重绘，避免高面数真实道具持续空转。加载失败仍报告错误，不偷偷替换成方块。

## 验证范围

- 面积增长和真实资产尺寸一致性。
- 70种长宽/铺型组合，共280个生成方案：不越界、不重叠、不侵占预留通道，至少1张体验桌。
- 被拖进通道的道具、错误备份通道数据应被检出。
- 白模/两种材质场景几何清单一致，三种状态各八视角均有不同画面；异步资产完成顺序不影响几何比较。
- 浏览器保存/恢复/导入/导出与窄屏回归；旧测试不再把固定4件道具写成保存功能的前提。

## 使用与边界

最终检查：默认回归95通过、9项专项默认跳过；单独启用生产版专项5/5通过；生产构建成功。3D公共包仍约646kB并触发构建体积提醒。截图保存于本地output/web-qa/20260927-finished-light.png、20260927-finished-dark.png和20260927-white.png。

推送前检查发现LFS dry-run枚举旧资产；已确认相对origin/main的原始PDF/SKP指针除行尾外无差异（对象哈希与大小不变），因此代码推送时仅对本次命令禁用LFS载荷上传，保留现有远端资产状态，不上传本机大文件。

启动E盘 demo 并新建尺寸方案即可使用新生成器。旧方案如只需要新材质表现，可以进入白模后重新渲染；新数量和通道需新建方案，避免覆盖已有编辑。

本机真实GLB位于demo/public/assets/su，随Git代码克隆不会自动获取这些本地文件。当前矩形空间的入口、灯轨和墙体仍是设计假设。参考了现有S03效果图的浅色展陈表达，没有把它作为已验收的整店模型。SI1/SI2选项为参考环境，90资产的SI标签仍保持未知。

渲染改进属于可用的实时材质方案预览，尚不能宣称与专业离线渲染、实店照片或品牌SI验收等价。完整边界、墙柱入口和品牌材质仍需逐店证据；没有启动新训练、AI图生成、付费服务或部署。
