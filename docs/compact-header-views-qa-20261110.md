## API 首轮独立验证

四阶段 CRUD、并发首次初始化、节点设计载荷不变、仅重命名时成图保持有效、位姿修改判旧且保留原背景、按新位姿重渲染通过。

初始化零结果复现。删除空间全部视角，在没有保存视角的既有方案上调用初始化，返回 200 和 0 条。恢复父空间一条视角，再调用该方案的初始化，返回 200 和 1 条。第一次结果为空时没有写任何持久记录，下一次仍按未初始化状态读取父节点。普通的并发初始化和已初始化节点全删后保留删除记录是不同路径。隔离证据见 `compact-header-views-qa-evidence-20261110/api-review.json`。

补测确认，复制渲染节点会为视角分配新 ID，保留位姿，不复制背景图片引用和背景修订号。方案节点提交背景字段返回 409。独立 Fastify/PGlite 脚本为 `review-api.mjs`，结果为 `api-review.json`，两者均在外置证据目录。

### 镜头位姿与成图版本复验

在最新 API 候选上独立验证。有背景的视角改名保持版本 1，材质图仍有效。改 FOV 后版本推进至 2，旧图标记过期，照片、变换、遮罩、辅助线和墙体设置全部保留。旧版材质 PNG 上传及旧版背景保存均返回 409，当前版本材质上传返回 201 并恢复有效状态。无背景旧视角第一次不带版本可上传，改位姿后不带版本和显式版本 0 均返回 409，版本 1 返回 201。随后仅切换辅助线显隐会推进修订号，现有成图保持有效。证据为外置目录中的 `review-pose-revision.mjs` 和 `pose-revision.json`。浏览器内的镜头调整与背景撤销组合等待前端候选。

### 已知限制

节点产生首条视角记录后，即使记录已软删除，也会保留独立的视角集合。尚无任何视角记录时，初始化仍从最近配置过视角的父节点继承。父空间的视角全部软删除时，无视角记录的子方案首次初始化返回 0 条。恢复父空间一条视角后，再次初始化同一子方案会继承 1 条。这条路径只影响从未建立视角记录的子节点。已有子节点视角仍按自己的记录读取，软删除记录持续生效。此轮保留该语义，以维持现有数据结构及项目导入导出兼容。复验证据见 legacy-edit-fixed.json。

项目菜单关闭、桌面与缩放布局、四阶段视角操作、旧 edit 节点兼容、渲染版本保护、背景撤销和交付主流程均已复验。专项中未发现其他正确性阻塞。
