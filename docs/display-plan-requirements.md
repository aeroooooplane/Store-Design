# 展陈方案需求

状态：**已确认**（2026-10-14，用户确认全部按推荐执行；同日补充：只出可编辑的 PPT，并回答了指引里的 4 处疑问）。按第 9 节分步实现，全部由展陈窗口完成。

## 1. 依据与现状

**规则来源**：飞书《影石专卖店中岛桌&边桌&配件柜展陈指引》（`https://arashivision.feishu.cn/wiki/NwOVw5xTAiFcvGkn8TZcjEO1nNh`，2026-10-13 版，访客可读）。指引随新品上市更新（文中有“10/20 上新，10/21 完成更新”），因此系统把规则当作**可替换的数据**，不写死在代码里。

**交付样例**（指引第一节“案例参考”）：深圳海岸城边厅店（3 桌竖版）、深圳万丰海岸城边厅店（4 桌横版）、台湾台北信义商圈 A9T 店（4 张中岛桌 + 2 张边桌）。美国纽约时代广场店那份是幻灯片，需要登录，未查看。

**同事的展陈 PPT 工具**：`资源库/08-skill/展陈方案生成/`（Python 本地网页工具，未纳入 Git）。上传门店 PDF 或图片，识别平面图上的中岛桌并编号，拖动标签校准、切换横竖、增减桌子，最后输出可编辑的 PPT，相当于本文的工作流 2。本项目借鉴它的界面流程、编号规则、PPT 版面和 10 套 2026 年新店图纸（附带每店的桌数、横竖和标签位置，可作为回归测试集）。不直接运行它的代码，原因有三：产品布置写死在代码里，且是 6 月“Luna 上市”的旧版；产品照片按固定坐标从 PDF 裁切，指引改版后会切错；本项目和 CI 都没有 Python。

**现有系统**：交付生成两份 A3 横版 PDF（完整版、展示版，见 [需求](requirements.md) 第 7 节）。布局只有道具清单，没有产品数据；三维模型上的样机是通用摆件，不代表实际陈列。第二期识别可从门店平面图读出道具（`apps/api/src/modules/recognition/`）。

**调研结论（2026-10-12～14）**：

- 历史图纸：`资源库/01_各门店原图纸` 的 513 份 PDF 中，244 份标有“明星展位”，189 页写明了中岛桌系列。2 张桌多为 X + GO（55 例），3 张桌多为 X + GO + ACE（59 例）或 X + X + GO（39 例），与指引的“按桌数排布”一致。
- 平面识别（矢量 PDF，本地）：抽样 23 个平面页，有标注的 18 页里 16 页中岛桌张数完全正确，按张数约 90%；边桌约七到八成。
- 平面识别（图片，千问 Qwen3-VL）：2 张测试图的中岛桌全部找到，并读出了系列。模型会把开箱桌、收银台也算进来，但读出的文字写着“开箱桌”“收银台”，按文字即可过滤。
- 效果图识别（千问）：框的位置准，但“哪个框是平面上的哪张桌”只对了约 1/4～3/5，每次 10～20 秒。因此效果图标签采用“模型先框、用户拖动确认”。

## 2. 定义与范围

**展陈方案**：按店内中岛桌的张数和朝向，套用指引中的陈列布置，给出每张中岛桌和带托盘边桌的每个托盘位放什么产品、桌子中间放哪些配件模块，汇总产品数量明细（运营用）和托盘数量明细（供应商用），并在平面图和效果图上标出每张桌。

| 读者 | 用途 |
|---|---|
| 门店运营 | 按桌、按位出样（真机从大货中出样） |
| 托盘与物料供应商 | 按托盘数量明细备货 |

**第一期范围**：指引第一至三节，即中岛桌、带托盘边桌的主机陈列和中岛桌的模块化配件托盘。指引第四节（配件柜托盘、配件柜灯箱、磁吸画）放到后续。

**不包括**：价格、库存，轴侧示意图，在效果图里换上真实产品模型。

## 3. 规则（摘自指引）

1. **按中岛桌张数选版式**：2 / 3 / 4 张桌各有一套，每套分竖版和横版。1 张或 5 张及以上属于“非标准桌，单店单议”：套用最接近的版式，标“单店单议”，由用户逐位修改。
2. **每张中岛桌 7 个托盘位**：6 个普通位加 1 个端头位。竖版的明星展位在端头，横版的明星展位在靠主人流一侧的中间。指引原话：“陈列上仅对中间位和端头位进行调换”。**竖版的端头朝入口一侧**；横版的端头所有中岛桌统一朝一个方向，默认按指引示意图画在左侧（面向主人流时），用户可以整体翻转。
3. **桌号**：“*-1 表示离门口更近，曝光更好，*-2 次之，以此类推”。具体做法沿用同事工具：把平面旋转到入口在下方，从离入口最近的一排开始，每排从左到右编号；前后距离相差不到桌宽一半的算同一排。
4. **竖版 / 横版**：以离入口最近的那张中岛桌为准，长边与主人流方向接近垂直为竖版，接近平行为横版；全店统一用这一种。主人流方向沿主入口所在的边。
5. **边桌**：带托盘的边桌一律 3 个位，放 Ace Pro 2、X5、GO Ultra；竖版和横版只是方向不同。
6. **中间配件模块**：外框分 ADDA、ABA、ACA 三种组合（SI1.0 和 SI2.0 外框不同）；模块按尺寸分 A / B / C / D，编号对应产品系列（如 C3 自拍杆系列、D8 AG 系列）。每个桌号的默认模块见附录 A.4。**产品以指引第一节（最新版）为准；第三节只用来确定桌子中间的配件模块**，其图中摆的产品不采用。
7. **其他数量规则**：iPad 数 = 中岛桌数 + 1，如有 AG 配件柜再 + 1；笔记本数 = Link 数量；自拍杆摆放长度 114 cm。
8. **SI1.0 和 SI2.0 的陈列方案通用**，只有托盘的款式不同（指引第二节分别列出了 SI1.0 和 SI2.0 的托盘）。
9. **名称**：统一用 AG（不用 AVBU）、Ace Pro 2（陈列位示意中沿用指引的简写 AP2）。

规则的具体内容见附录 A。

## 4. 两个工作流

### 4.1 工作流 1：系统内的项目（先做）

在渲染节点上生成，数据都来自系统：

1. 中岛桌 = 布局中用途为 `island_table` 的道具；带托盘边桌 = 模型库中名称含“带托盘”的边桌或配件边柜（在目录导入时标记 `trays: true`）。
2. 主入口取空间的第一个入口段；按第 3 节规则 3、4 自动编号、判断竖版或横版、套用版式和配件模块。
3. 平面标签：浏览器导出“展陈平面”PNG，在每张桌的位置贴红色字母标签。
4. 效果图标签：渲染节点的相机参数已知，把桌面中心投影到每张材质图上即得到标签位置，并按深度判断是否被遮挡。每张桌自动选一张它最显眼的效果图，用户可以换。
5. 用户可在“展陈”页签里改任意位的产品、模块和桌子顺序；修改**不让效果图过期**。
6. 生成交付文件时勾选“同时生成展陈方案”（有中岛桌或带托盘边桌时默认勾选），交付目录多出 `影石xxx店展陈方案.pptx` 和 `04_展陈方案/`；页签里也能单独生成并下载。

### 4.2 工作流 2：上传平面图和效果图（后做）

不建正式项目，建一个轻量的“展陈任务”，但数据结构与工作流 1 相同，并记下识别结果的编号，以后可以转换成项目。页面流程参照同事工具：输入 → 校准（拖动编号、切换横竖、增减桌子）→ 输出。

1. 上传一张平面图（矢量 PDF 选页，或 JPG / PNG，质量与现有门店图纸相当）和一张效果图。
2. 平面识别复用第二期的识别：矢量 PDF 走本地识别，图片走视觉模型；再按标注文字过滤出中岛桌和边桌，读出系列、主入口与主人流方向的文字。
3. 用户在平面图上确认：增删桌子、拖动位置、改朝向；识别不到主入口时由用户点选。
4. 效果图：视觉模型框出桌子，并按平面识别结果先猜一遍对应关系；用户拖动标签到正确的桌子上，也可以自己放标签。
5. 按规则生成展陈方案，下载 PPT 和 Excel。每个任务约调用 2 次视觉模型（约 0.02 元），计入每日 AI 预算；没有可用模型时，平面只能走本地识别，效果图标签由用户自己放。

## 5. 交付版式

以台北案例为准，并参考两个深圳案例和同事工具的版面。**只输出可编辑的 PPT**：`影石xxx店展陈方案.pptx`，16:9 横版（13.33 × 7.5 英寸）。标题、陈列位示意、标签、数量明细都用 PPT 原生的文本框、形状和表格，运营可以直接修改；效果图、平面图和托盘照片作为图片嵌入。字体用微软雅黑（同事工具相同，Windows 和 Mac 的 Office 都有）；需要 PDF 时在 PowerPoint 中另存。用开源的 Node 库 pptxgenjs（MIT 许可）生成。

| 页 | 内容 |
|---|---|
| 封面 | 黑底，“影石Insta360”，店名，“中岛桌展陈方案”，日期 |
| 平面布局总览 | 左侧黑栏放标题和一张效果图（贴全部标签）；右侧放平面图，每张桌贴红色字母标签（A、B、C…按桌号顺序，边桌接续字母）；下方放各桌的版式缩略（如“4-1 中岛桌（竖版）”），明星位红框 |
| 每张中岛桌一页 | 左侧黑栏：“平面布局图 A桌”，下面是效果图和平面缩略，都在这张桌的位置贴“A桌”标签；右侧：这张桌的托盘位示意（产品名，明星位红框，标注主人流方向），中间配件模块条写模块号；两边用虚线连到对应托盘的照片 |
| 每张边桌一页 | 同上，3 个位 |
| 数量明细 | 产品数量明细（运营用：类目 / 型号 / 数量 / 小计 / 总计）和托盘数量明细（供应商用：托盘种类 / 托盘位数量 / 总计），版式同指引里的表；另列 iPad、笔记本数量和自拍杆长度说明；“单店单议”等待确认事项列在页末 |

`04_展陈方案/`：`展陈清单.xlsx`（工作表：逐桌逐位明细、产品数量、托盘数量、配件模块，数字与 PPT 一致）、`展陈平面.png`、贴好标签的效果图。工作流 2 的下载包内容相同，但不进交付目录。

完整版与展示版不变；完整版只在“概况”里加一行“展陈：中岛桌 N 张、边桌 M 张，见《影石xxx店展陈方案》”。

## 6. 数据模型草案

### 6.1 规则与图库（命令行导入，网页只读）

源文件放在 `资源库/10_产品与陈列/`：`展陈规则.xlsx` 由展陈负责人随指引更新，托盘照片放在 `托盘图库/`。工作表如下：

| 工作表 | 列 | 说明 |
|---|---|---|
| 产品 | 编号、名称、类目（无人机 / X / Ace / GO / Flow / Link / Mic / Luna）、海外名称、状态 | 一个托盘可放多件产品，如“X5 + X4 Air” |
| 托盘 | 编号、名称（如“X系列托盘（含Ace）”“Luna托盘A”）、SI1.0 图片、SI2.0 图片 | 照片取自指引第二节的效果图和实景图 |
| 版式 | 桌数（2/3/4/边桌）、桌号（如 3-1）、竖横、位号、产品、托盘、是否明星位 | 附录 A.1–A.3 |
| 配件模块 | 模块号、系列、尺寸类别、图片 | 附录 A.4 |
| 桌号默认模块 | 桌数、桌号、外框组合、模块号列表 | 附录 A.4 |
| 说明 | 版本日期、iPad / 笔记本 / 自拍杆规则文字 | 写进 PPT 与交付记录 |

位号统一编号，使竖版和横版可以对照。竖版：左列从远到近为 L1–L3，右列为 R1–R3，端头为 E（明星位）。横版：远侧一排从左到右为 T1–T3，靠主人流一侧为 B1–B3（B2 为明星位），端头为 E。

导入后存入数据库的规则表，带版本日期；每次生成都把所用版本写进记录。**指引因新品上市调整时**：展陈负责人按飞书最新版修改 Excel 并重新导入。导入命令会列出与上一版相比改动了哪些桌、哪些位、哪些数量，并核对每种桌数下各位产品之和是否等于数量明细，不一致时拒绝导入。已生成的方案和交付记录保留生成时的版本，不受影响；在展陈页签打开旧方案时，提示“规则有新版本”，并可一键按新版本重排。

### 6.2 项目数据

两个工作流共用 `DisplayPlan` 结构（`packages/shared/src/display/`）：

```ts
interface DisplayPlan {
  version: 1
  ruleVersion: string              // 展陈规则.xlsx 的版本日期
  entrance: { x: number; z: number } | null
  tables: DisplayTable[]
  notes: string[]
}
interface DisplayTable {
  label: string                    // 'A'、'B'…
  kind: 'island' | 'side'
  layoutItemId: string | null      // 工作流 1：布局道具
  plan: { cx: number; cz: number; w: number; d: number; rotation: number } // 平面位置（米；工作流 2 为识别后的平面坐标）
  orientation: 'portrait' | 'landscape' // 竖版 / 横版
  rule: { tables: number; seat: string } // 采用的版式，如 { tables: 4, seat: '4-1' }
  slots: Record<string, { products: string[]; tray: string; hero: boolean }> // 默认取自规则，可改
  modules: string[]                // 中间配件模块
  marks: { imageId: string; x: number; y: number; source: 'projected' | 'detected' | 'manual' }[] // 效果图标签（0–1 相对坐标）
  custom: boolean                  // 非标准桌数或被用户改过
}
```

- 工作流 1：新表 `node_displays`（渲染节点主键，`plan` JSONB，`revision` 乐观锁）。
- 工作流 2：新表 `display_tasks`（名称、上传文件编号、识别记录编号、`plan` JSONB、状态、生成记录）。将来“转为项目”时，用识别记录生成空间节点，再把 `plan.tables` 对应到布局道具。
- 交付记录 `交付记录.json` 增加 `display`：展陈快照（写名称而非只写编号）、规则版本、页序、文件哈希。

## 7. 识别与标签细节

- **平面中的桌子**：在识别结果上加一道筛选，按文字区分“中岛桌 / X 系列中岛桌 / 边桌 / 配件边柜（带托盘）”与“开箱桌、收银台”等；读出的系列（X / GO / ACE）只作参考，桌号仍按规则 3 排。
- **主入口与主人流方向**：用识别中已有的“主入口 / 主人流通道”文字判断；读不到时由用户点选入口边。
- **SI 版本**（工作流 2）：项目没有 SI 信息，默认按同事工具的做法从效果图判断（靠墙桌与主色调为黑色是 SI2.0，白色是 SI1.0），用户可改；SI 版本只决定托盘照片用哪一套。
- **效果图**：视觉模型返回各桌的框（0–1000 相对坐标）。把平面上的桌子清单（字母、大致位置）一起发给模型，让它先猜对应关系。模型输出只用来放初始标签，最终以用户拖动的位置为准。
- **识别失败**：视觉模型不可用或超出预算时，平面走本地识别，效果图标签全部由用户手动放置。

## 9. 分步计划

每步一个 PR，CI 通过后合并：

1. **规则数据与规则引擎**：把指引转写成 `展陈规则.xlsx`（附录 A 即初稿），托盘照片入图库；导入命令（含与上一版的差异报告）；shared 中的规则引擎（按桌数选版式、按排编号、判断竖横、套模块、汇总数量）与单元测试；CI 直接读取仓库里的 Excel 核对总数。不碰交付模块。
2. **展陈 PPT 与 Excel 排版**：新模块 `displays/`，用固定样例数据排出与台北案例同版式的 PPT，在 PowerPoint 中打开逐页核对，确认文字可编辑。只新增文件。
3. **工作流 1**：`node_displays`、展陈页签、展陈平面与效果图标签投影、交付接入。**会改交付模块**，开始前与其他窗口约定错开时间。
