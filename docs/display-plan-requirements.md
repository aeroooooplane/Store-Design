# 展陈方案需求（草稿）

状态：**草稿，待确认**（2026-10-12）。本文按第 11 节“待确认问题”的推荐选项编写；问题答案与推荐不同时相应修改。确认后把结论并入 [需求文档](requirements.md) 第 7 节与决策记录，再进入设计与实现。

## 1. 背景与现状

- 交付（[需求](requirements.md) 第 7 节、[架构](architecture.md) 4.4）目前生成两份 A3 横版 PDF：完整版 = 平面页 + 效果图总览 + 每个材质视角一页；展示版 = 首页平面图 + 每页一张材质图。交付目录为 `01_平面图 / 02_效果图 / 03_源文件与记录`。
- 布局只有道具清单（模型编号、用途、位置、尺寸），平面图例编号由 `deliveryLegend` 生成。系统里**没有产品 / SKU 数据**。效果图中台面上的样机是模型自带的通用摆件（如“1.8米普通中岛桌_产品陈列A”），不代表具体陈列。
- SI1.0 / SI2.0 手册没有独立的“展陈方案”章节，相关内容分散在布局区域、配件柜配置、验收标准、KV 尺寸等页面（见第 3 节）。
- 历史门店图纸里的展陈是**画在施工图上**的：对 `资源库/01_各门店原图纸` 现有 513 份 PDF 做文字扫描（1 份读取失败），约 320 份在平面或大样图上写了产品名，244 份标有“明星展位”，249 份出现“X 系列 / GO 系列中岛桌”。在 244 份标有明星展位的图纸中，各产品出现的门店数为：GO 3S 238、X5 233、Ace Pro 2 230（其中“街拍”228）、Flow 2 Pro 206、Link 2 176、X4 172、X3 170、Ace Pro 163、Flow 2 115。配件、灯箱画面在图纸上几乎不写具体内容。

## 2. 定义与读者

**展陈方案**：在已确定的软装布局上，规定每件陈列道具的每个陈列位放什么产品、配件和陈列物料，汇总门店要准备的样机、物料和画面，并附陈列原则与禁忌。

| 读者 | 用途 |
|---|---|
| 门店运营 / 代理商（主要） | 开业布置、日常补位，对照位号摆放 |
| 道具与物料供应商（次要） | 按清单备托盘、支架、价签、iPad、灯片 |
| 品牌 / 区域审批 | 看总览页了解主推产品与明星展位 |

不面向商场审图：展示版不变。不包括：价格、库存与销售数据，真实产品的三维模型，画面设计稿。

补充参考：SI2.0 第 25 页“布局主要配置汇总”（引流区 / 体验区 / 陈列区 / 服务区分栏，可用于总览分区）；`上海第一八佰伴授权体验店.pdf` 第 2 页（平面布置图上直接标产品与明星展位，说明总览平面需要区分同款道具的不同配置）；`深圳前海壹方城.pdf` 第 21 页（产品道具平面图：产品支架按实物定制、产品参数牌、iPad、灯箱）。

陈列原则可摘录的手册内容：

- 布局优先：引流区 > 体验区 > 陈列区 > 服务区 > 后勤区；体验区 1.8 米中岛桌优先，陈列区配件柜优先于边桌配件柜（SI1.0 PDF 第 28 页）。
- 主要通道 900–1200 mm，例如中岛桌周围、配件柜前方（同上）。
- 中岛体验台：亚克力托盘 + 产品支架，充电防盗；产品陈列稳固、屏幕不晃动；价格签、视频播放顺序与产品陈列对应；视频为最新版本，3 米内字幕清晰（SI1.0 验收标准印刷页 185；现存 PDF 未收录这一部分，文字见 `05_店铺形象设计标准/历史阅读记录/逐页文字与阅读索引.json`）。
- 配件包装盒按类别整齐陈列，标签清晰，便于顾客识别选购；iPad 至少第 9 代（同上，印刷页 186）。
- KV 规格首选 2400×1270，次选 2000×1270，竖版 900×1600；顶部离地 2400；元素不得变形（SI1.0 PDF 第 141 页）。广告机 / 灯箱上沿统一 2400 mm（SI2.0 第 42 页）。
- 横屏配横图、竖屏配竖图，不拉伸、不镜像；未授权图片只作演示（Skill《灯箱与广告画面规则》）。
- 门店分级对陈列区的要求：S 级配件灯箱，A1 / A2 / B 级画面灯箱（SI1.0 PDF 第 25 页）——项目目前不记录门店等级，第三期再用。

## 4. 范围与分期

| 期 | 内容 |
|---|---|
| **展陈第一期** | 产品库、陈列位、陈列模板、陈列原则四类目录数据（命令行导入，网页只读）；渲染阶段新增“展陈”页签：套用模板、逐位改产品与数量；生成交付时可同时生成第三份 PDF《影石xxx店展陈方案.pdf》（总览、道具陈列页、样机与物料清单、陈列原则）和 `04_展陈方案/展陈清单.xlsx`。灯箱与屏幕只列出位置、尺寸和横竖，画面写“待定 / 品牌提供” |
| 展陈第二期 | 画面库与选图（来源、授权状态按 Skill 规则记录），画面页（参考样例 ②）；选定的画面贴到三维与效果图上（会改变渲染结果）；总览平面按引流 / 体验 / 陈列 / 服务区着色 |
| 展陈第三期 | 设计助理增加“套用模板 / 批量换产品”工具；按门店等级、面积推荐模板；新品上市时批量提示受影响的项目 |

实现按以下步骤拆 PR（每步 CI 通过即合并），前两步不碰交付模块：

1. 目录数据：数据结构与校验（`packages/shared`）、数据库表与导入命令、只读 API。
2. 项目展陈数据：`node_displays` 表、读写 API、前端“展陈”页签。
3. 展陈 PDF 与交付接入：新增展陈排版，从 `deliveries/pdf.ts` 抽出公共排版函数，`deliveries/service.ts` 接入第三份 PDF、Excel 与交付记录（**会改交付模块，需要与另一窗口错开**）。
4. 第二期：画面。

## 5. 数据模型草案

### 5.1 目录数据（命令行导入，网页只读）

源文件放在 `资源库/09_产品与陈列/`（新目录），格式与模型选用表一致，用户可直接在 Excel 里改。

**产品库**（`产品库.xlsx` → 表 `products`）

| 字段 | 说明 |
|---|---|
| id | 稳定编号，如 `x5`、`ace-pro-2-street`，由表格给出，改名不改编号 |
| name / nameEn | 国内名称 / 海外名称（海外项目用英文名） |
| series | X、GO、Ace、Flow、Link、AVBU、配件、演示设备 |
| kind | 相机、云台、无人机、配件、演示设备（iPad、电视等） |
| variant | 颜色或套装，如“黑”“白”“街拍套装” |
| skuCode | 可选 |
| fits | 配件适配的产品编号（配件才填） |
| status | 主推 / 在售 / 停售 |
| image | 白底产品图（可缺，缺时 PDF 只写文字） |

初版由我按历史图纸统计的型号（第 1 节）和模型库里出现的 GO Ultra、X5、ANTIGRAVITY 起草，用户补全在售状态、颜色、套装与产品图，之后由用户维护。

**陈列位型**（`陈列位.json` → 表 `display_layouts`）：一类陈列道具的陈列位布置，多款同尺寸模型共用。

```ts
interface DisplayLayout {
  id: string                   // 如 'island-1800x800'、'cabinet-1200'、'side-cabinet-1800-tray'
  name: string                 // '1.8米中岛桌（6 托盘 + 明星位）'
  view: 'top' | 'front'        // 中岛桌、边柜画俯视；配件柜画正立面
  size: { w: number; h: number } // 毫米，俯视为宽×深，立面为宽×高
  slots: DisplaySlot[]
  assetIds: string[]           // 使用这一布置的模型
}
interface DisplaySlot {
  id: string                   // 位号 '01'、'02'…，示意图与表格共用
  kind: 'hero' | 'device' | 'accessory_tray' | 'ipad' | 'shelf' | 'tray' | 'lightbox' | 'logo'
  rect: { x: number; y: number; w: number; h: number } // 毫米；俯视与模型平面符号同一坐标（正面朝下），立面从地面起算
  accepts: ProductKind[]       // 可放的产品类别
  capacity: number             // 最多几件（层板为面位数）
  fixtures: string[]           // 该位自带的陈列物料，如 ['托盘', '产品支架', '亚克力价签']
}
```

陈列位由我按模型平面符号（`平面图.svg`，1 单位 = 1 mm）和历史大样图（参考样例 ①）标注，用户审核。第一期覆盖：1.8 米中岛桌（SI1.0 / SI2.0 / 亮脚款）、1.8 米配件边柜（带托盘）、边桌配件柜、1.2 / 1.6 / 2.4 / 3.6 米配件柜、600 方产品展示台、试飞台；没有陈列位型的道具（收银、开箱桌、坐凳等）不进入展陈。

**陈列模板**（`陈列模板.xlsx` → 表 `display_templates`）

```ts
interface DisplayTemplate {
  id: string                   // 'island-x'、'island-go'、'cabinet-1200-insta360'…
  name: string                 // '1.8米中岛桌 · X 系列'
  layoutId: string             // 只能套用到同一陈列位型
  siStyles: ('SI1.0' | 'SI2.0')[]
  assignments: { slotId: string; productId: string | null; qty: number; note?: string }[]
  source: string               // '七宝领展 X 系列中岛桌大样图' 或 'SI2.0 第 116 页'
}
```

初版：中岛桌“X 系列 / GO 系列”两套（依据参考样例 ①，产品换成当前在售型号），配件柜按 SI2.0 第 116 页的四种组合，配件边柜、展示台各一套。模板直接写产品编号；含停售产品时提示更新，不自动替换。

**陈列原则**（`陈列原则.json` → 随目录导入）：`{ id, group, text, siStyles, source }`，分组为“布局与动线 / 中岛桌 / 配件柜 / 画面与屏幕 / 禁忌”，`source` 写手册与页码（第 3 节所列）。

### 5.2 项目数据

展陈挂在**渲染节点**上（与视角相同的位置），新表 `node_displays`：

| 字段 | 说明 |
|---|---|
| node_id | 渲染节点（主键） |
| plan | JSONB，见下 |
| revision | 乐观锁，写接口要求 `If-Match` |
| updated_at | |

```ts
interface DisplayPlan {
  version: 1
  items: Record<string /* 布局道具 id */, {
    templateId: string | null
    slots: Record<string /* 位号 */, { productId: string | null; qty: number; note?: string }>
    note?: string
  }>
  notes: string[]              // 项目追加的陈列说明
}
```

- 修改展陈**不改变布局签名，不让效果图过期**（效果图里的样机是通用摆件）。
- 新建的渲染节点展陈为空；页签提供“按默认模板填充”和“从其他渲染节点复制”（按道具 id 对应，对不上的列出）。
- 展陈不新增历史阶段，历史树不变。

### 5.3 校验（`packages/shared`，前后端共用）

| 情况 | 级别 |
|---|---|
| 产品不存在；产品类别不在该位 `accepts` 中；数量超过 `capacity`；模板与道具的陈列位型不符 | 错误，不能保存 |
| 产品已停售；陈列道具没有任何产品；陈列位为空 | 待确认，不阻止保存与交付，PDF 中列出 |

### 5.4 交付记录增量

`交付记录.json` 增加 `display`：展陈快照（每件陈列道具的配置、位号、产品名称与数量、模板与来源）、待确认条目、展陈 PDF 页序、Excel 文件哈希。快照写入名称而非只写编号，产品库以后变化不影响已交付的记录。

## 6. 页面版式（文字描述）

第三份 PDF《影石xxx店展陈方案.pdf》：A3 横版，页眉、页脚、字体、黄色编号徽标与现有两份 PDF 一致；页脚“影石xxx店 · 展陈方案 · 日期 · 页码”。

**页 1 展陈总览**
- 左侧约 2/3：展陈平面。与交付平面同一张图，陈列道具的徽标改为“图例号-序号”（如 `01-1`、`01-2`），旁边加配置简称（“X 系列”“GO 系列”），以区分同款道具的不同配置（参考上海第一八佰伴平面）。由浏览器与交付平面一起导出。
- 右侧：陈列道具列表（`01-1 1.8米中岛桌 · X 系列 · 明星位 X5`）；概况（样机 N 台 / M 款、配件面位数、价签与卖点卡数量）；待确认条目（空位、停售产品）。

**页 2…n 道具陈列页**（每种不同配置一页，配置相同的道具合并，如“01-1、01-3”）
- 标题：`01-1 1.8米中岛桌 · X 系列`，副标题写模板名与来源。
- 左侧约 60%：陈列示意图。俯视类用模型平面符号作底图，按陈列位画框和黄色位号，框内或旁边写产品名；明星展位红色虚线框并标“明星展位”；标注总尺寸（参考样例 ①）。配件柜用正立面示意：灯箱、层板分区（写“X5 配件”等类目）、托盘、iPad 位（参考样例 ②）。
- 右侧：陈列位表（位号 / 产品 / 颜色或套装 / 数量 / 陈列物料 / 备注），下方放模型效果图缩略与本道具备注。

**清单页**（参考样例 ③，内容多时续页）
1. 样机：按产品汇总数量，列出所在位号（`01-1·03、01-3·03`）。
2. 配件：类目 × 适配机型 × 面位数。
3. 陈列物料：托盘、产品支架、亚克力价签 / 卖点卡、iPad 及支架、LOGO 柱等，由各陈列位的 `fixtures` 汇总。
4. 画面与屏幕：位置、设备、可视尺寸、横 / 竖；第一期画面一栏写“待定 / 品牌提供”。

**最后一页 陈列原则与禁忌**：按分组列出条目并注明出处，项目追加的说明另列一组。

页数 = 1 + 不同配置数 + 清单页数 + 1。

**交付目录**新增 `04_展陈方案/`：`展陈清单.xlsx`（工作表：陈列位明细、样机汇总、配件、陈列物料、画面与屏幕，数字与 PDF 一致）、`展陈平面.png`。第三份 PDF 放在目录根部，与另两份 PDF 并列。

**完整版与展示版**：展示版不变（双 PDF 规则不允许文字页）；完整版只在“概况”加一行“展陈：陈列道具 X 件，样机 N 台，见《影石xxx店展陈方案》”。

## 7. 网页交互（概要）

渲染节点新增“展陈”页签（与“渲染图”并列）：
- 左侧平面，陈列道具高亮并显示 `01-1` 编号；点选道具后右侧显示该道具的陈列示意（与 PDF 同一画法）。
- 选择模板（只列出同一陈列位型且适用当前 SI 风格的模板）→ 一键套用；逐位从产品库选择产品、改数量与备注。
- 底部显示待确认条目与汇总数量；“按默认模板填充全部”“从其他渲染节点复制”。
- 生成交付文件时增加勾选“同时生成展陈方案”，有展陈数据时默认勾选。

## 9. 验收标准（第一期）

1. 四类目录数据可用命令导入，重复导入结果不变；停售产品保留并标记。
2. 布局中引用了有陈列位型的模型的道具都出现在“展陈”页签，其他道具不出现。
3. 套用模板后各陈列位有产品或明确为空；手工修改保存后刷新仍在；修改后布局签名不变，效果图不标过期。
4. 类别不符、数量超容量、模板与陈列位型不符时不能保存，并提示原因；停售产品、空位列为待确认。
5. 勾选后交付目录多出第三份 PDF 和 `04_展陈方案/`；页数 = 1 + 不同配置数 + 清单页数 + 1；不勾选时交付内容与现在一致（现有两份 PDF 的页序不变）。
6. 示意图位号与陈列位表一一对应，明星展位为红色虚线框；样机汇总等于各陈列位数量之和，价签数等于放了样机的陈列位数，PDF 与 Excel 数字一致（单元测试覆盖）。
7. 空位与停售产品出现在总览“待确认”和清单备注中，不阻止生成；交付记录写明待确认数量。
8. 海外项目的产品名用英文名，其余文字为中文。
9. 展示版不变，完整版只多一行概况。
10. 交付记录含展陈快照；之后修改产品库或项目展陈，不影响已交付的文件与记录。
11. 逐页渲染检查：中文正常、不裁切、A3 横版，页眉页脚与现有两份 PDF 一致。
12. 类型检查、单元测试与 API 测试在 CI 通过。

## 12. 风险与未决

- 产品库的准确性取决于用户维护；历史图纸只覆盖到 2025 年的型号，新品（如 GO Ultra、ANTIGRAVITY）需要用户确认名称与在售状态。
- 历史大样图的中岛桌有 1800×1000（七宝领展）与 1800×800（武汉大悦城、SI2.0）两种，陈列位型要按模型实际尺寸分开。
- 配件柜的层板数量、灯箱尺寸在手册中只有效果图，没有尺寸图；第一期按模型实测标注，标为“示意”。
- AVBU 托盘、头盔托盘等物料的规格需用户补充，缺失时清单只写名称与数量。
