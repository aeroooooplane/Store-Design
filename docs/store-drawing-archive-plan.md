- **目标**：每份内容不同的 PDF 建一份门店档案，共 511 份。内容完全相同的文件只保留一份，其余记为别名；没有 PDF 的门店不建档。平面图结构化成工作台能直接打开的数据。

  - 每店记录软装道具、信息化物料等五大类道具的数量（第 2.9 节）。
  - 效果图按视角和干净度归类。
  - SI 和铺型以飞书 10-09 台账为初值，用图纸证据核对，冲突交给人工裁决。
- **做法**：先全量建好目录、标签和页面分类；平面结构化先做 40 家人工确认的“金标准”，再全量自动跑并分级抽检。金标准同时作为识别功能的回归测试集。识别失败的门店只记录、不调用视觉模型。

## 2. 目标：整理成什么样（已确认方案）

### 2.1 核心概念

```
（商场组：同一商场 / 地址，用于防止训练数据泄漏——以后再做）
门店档案 store（每份内容不同的 PDF 一份，共 511 份；store_id 沿用主来源的 PDF-xxx / NEW-xxx）
    ├ 来源 source（PDF-xxx / NEW-xxx，带 SHA256；内容相同的其他文件名记为别名）
    │  └ 页面 page（类型、置信度、图号、标题）
    ├ 方案 scheme（通常只有 1 个；一份 PDF 里含多个楼层或比选方案时拆成多个）
    │  ├ 平面成果 plan（原页证据 → 结构化 JSON → 标准平面图）
    │  └ 道具与物料统计 bom（物料清单读数、平面计数）
    ├ 效果图 render（底图、视角、干净度、是否属于本方案）
    └ 关联门店 related（同铺位的其他档案及关系——以后再做）
```

- **为什么不再分“版本”层级**：按 Q3 的答复，同名但内容不同的 PDF 当作两家店。所以 18–23 组同店多文件不做版本归并，改用“关联门店”互相连接，并记录关系类型和日期证据。
- **规则统计时的去重**：同一铺位的前后几份档案本不应算多个独立样本。关联门店推迟后，本次统计暂按每份档案计，报告中注明同铺位可能重复（约 18–23 组，占 511 份的 4% 左右）；等补上关联门店后，同一组只计设计日期最新的一份，训练 / 验证 / 测试集按商场组划分。
- **内容相同的两组**：成都环球中心与“（2F）”以前者为主来源；番禺天河城按 10-13 答复**只保留框架中岛**（NEW-040），无框架中岛记为别名，不拆成两个方案。
- **门店编号**：城市推迟后，按城市排序新编 ST-xxxx 的理由没有了；为免再多一套编号，store_id 直接沿用主来源的 source_id（PDF-001~418、NEW-006~101），取代 Q7 原推荐。

### 2.4 平面图：三层成果

1. **原页证据（全量）**：每份档案（多方案时每个方案）选定主平面页；记录页码、裁切框、旋转；无损导出原图平面.pdf 和预览 PNG。原图不改像素，不用 AI 修补。
2. **结构化 JSON（金标准 40 家人工确认，其余自动加分级）**
   - 先用工作台现有的本地矢量识别出草稿。金标准由我看图修正；全量阶段识别失败的，**只记入识别失败清单，不调用通义千问视觉模型**（Q15 答复）。
   - 每个方向至少用一条尺寸核对比例；校核边界闭合、入口和柱子位置、道具数量和型号。
   - 斜放道具在档案里保留真实角度，导入工作台时再取整。
3. **标准平面图（全量自动生成）**：由 JSON 生成统一风格的平面图（墙体填充、外包和分段尺寸链、道具符号、面积），复用工作台已有的平面绘制。这就是“矢量化 + 标尺寸”的成品。原图里的尺寸读数只在金标准里逐条记录。

### 2.5 效果图归类

- **归属**：门店 → 效果图。同一个 PDF 里的效果图默认属于这份档案；一份 PDF 里有多个方案时，标出属于哪个方案。
- **视角**：门头外观、正面全景、斜角全景、鸟瞰、道具特写、局部细节、其他。
- **干净度**：干净；有标注但能取到底图；标注已烤进图里；照片合成；现场照片；概念草图。
- **其他属性**：分辨率、是否碎片（需要按原页拼接）、底图 SHA256、来源页和区域。
- **存法**：从 PDF 提取底层原始位图，不改像素。标注是矢量叠加的就取底图；已经烤进图里的保持原样并打标记。按 SHA256 去重，保留所有出现位置。
- **不做**：不标每张效果图对应平面上的相机位置（人工量大）；只标“和本档案平面是否一致”。

### 2.6 SI 与铺型怎么判定

- **SI 挂在每份档案上**；同铺位改造前后是两份档案，可以不同。
  - 初值：飞书 10-09 台账，09-23 快照作对照。
  - 按证据强弱自动核对：
    1. 图纸文字：物料清单、材料表里的“si2.0 中岛桌”等字样（54 份有）。
    2. 道具特征：SI1.0 是白色圆角中岛桌 1800×1000、白色高脚凳、1.6 米配件柜；SI2.0 是深灰围边中岛桌 1800×800、黑色高脚凳、徕卡墙、Φ800 试飞台；材料表里的 1200×600 仿水磨石地砖。
    3. 效果图色调：白 / 浅银灰，还是深灰铝板配白台面。你在 09-25 确认过，黑色门头、墙面、展柜可以作为 SI2.0 的判断依据（`docs/si-source-recovery.md` 第 3 行）。
  - **单店不混用**（Q21 答复）：同一家店里 SI1.0 和 SI2.0 是完全分开的。如果一份档案里同时出现两套各自独有的道具，就判为冲突（可能是识别错、模板残留或飞书错），进入人工队列。现有 3 份同时出现两种字样，先按这条复核。
  - **现阶段倾向只作提示，不作判定**：你提到为消耗 SI1.0 库存，现在专区和中岛主要用 SI1.0，边厅主要用 SI2.0。但历史上大量边厅是 SI1.0（台账里边厅 357 家、SI2.0 只有 92 家），而且 SI2.0 启用时间不明，所以不用日期规则，也不按铺型推断 SI。只有当“专区 / 中岛 + SI2.0”这类组合出现时，在审核页上加一个提示。
  - 证据和初值一致，记为“自动确认”；有冲突或没有证据，进入人工队列。
- **铺型也挂在每份档案上**，取值沿用工作台的三值：边厅 / 中岛 / 专区。
  - 定义按 SI1 手册 part2 第 5 页：边厅两面或多面靠墙；中岛四周不靠墙、被通道环绕；专区是在超市、百货等主力店内部划出的区域。
  - 初值来自飞书。用三类证据核对：图签里的“【边厅店】 / 中岛店”字样、文件名括号、平面几何的靠墙边数。冲突进人工队列。
  - “框架 / 无框架中岛”记为子类；**半岛（三面开放）归边厅**，子类记“半岛”（Q23 答复）。“专区 / 边厅”这种值，主值取专区，备注保留原文，进人工队列。

### 2.9 道具与物料统计（Q：是否用表格记录每店软装道具数与信息物料数——做）

**有意义，所以做。** 理由：

1. **排布规则的底表**：`planner.ts` 的 `tablesForArea` 和 requirements.md §5 的“必选组合”，都要按铺型 × 面积统计每类道具的数量和搭配。这张表就是直接输入，以后导入 `layout_rules`。
2. **SI 的强证据**：物料清单里的道具名直接带 `si2.0`；道具型号本身也区分 SI（徕卡墙、试飞台、1.6 米配件柜等）。
3. **识别回归最容易确认的期望值**：核对“这家店有几张中岛桌、几台广告机”，比核对坐标快得多。金标准每家都给出计数，回归脚本可以直接比对道具召回率。
4. **信息化物料配置**：广告机尺寸和台数、电子水牌、KV 灯箱、LED 门头屏等，交付和展陈方案都用得上。
5. **两路对账**：有物料清单的店，用“清单数量”和“平面计数”互相核对，可以发现识别错误，或图纸前后不一致。

**分类**：沿用模型库的五大类，主要统计前两类，后三类同时记录：

| 大类 | 例子（模型库已有） |
|---|---|
| 软装道具 | 中岛桌、开箱桌、收银台 / 收银边柜、各尺寸配件柜、徕卡墙、试飞台、产品展示台、培训坐凳、字母凳 |
| 信息化物料 | 广告机（43–86 寸）、电子水牌、KV 灯箱、KV 画面、LED 门头屏、曲面 LED 屏 |
| 品牌标识 | 墙面 LOGO、吊挂 LOGO、双面侧招、产品标识 |
| 非标陈列 | 中岛陈列柜组合、L 形挡板、产品放大模型、橱窗场景道具、橱窗模特 |
| 环境设施 | 轨道射灯、消防栓箱 |

摄像头、货架、模特等清单里有、模型库里没有的项目，记“未映射”，保留原文。

**两个数据来源**：

| 来源 | 覆盖 | 可信度 | 做法 |
|---|---|---|---|
| 物料清单页（IN-03） | 56 份 | 高：设计方填写的数量 | 按文字坐标重建表格，读出名称、规格、数量、备注；数量为 0 的模板行也保留，标“0” |

**产出**：
- `bom.json`（每店）：每行记录图上原文、规范名、大类、assetId、尺寸、SI 专属标记、清单数量、平面计数、采用值、来源页、置信度、是否人工确认。
