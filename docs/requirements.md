# 需求确认文档

更新：2026-10-09。汇总 2026-10-08 至 10-09 的逐轮确认结果。本文档是重构的需求基线，变更需要在文末“决策记录”追加条目。

## 1. 产品定位

把门店效果图 Skill（`资源库/08-skill/`，规则 V2）的流程升级为网页产品：

```text
输入空间（手动绘制 / 上传简图识别）→ 校对空间与尺寸 → 自动生成软装布局（4 种策略）
→ 平面编辑 → 白模（可旋转、可拖拽修改）→ 默认 8 视角渲染（可增删视角）
→ 双 PDF 交付 + 归档目录
```

Agent 可以通过对话完成上述任一步骤的修改。

## 2. 访问与用户

- 开发阶段不做登录，所有访客看到并操作同一份公共数据；部署前加入用户系统。
- 当前不建用户表，不在业务表中放假用户 ID。会被用户隔离的数据在 [数据模型](data-model.md) 中标注“未来按用户隔离”。
- 当前约 3 人使用；加入用户系统后会增加。
- 部署：先在 Windows 本机运行，后续迁移到 Linux + Docker。

## 3. 空间模型

- 空间为**多边形边界 + 障碍物（柱、管井、楼梯、固定设施）+ 入口段 + 开放边**，不再限定矩形。
- 单位：界面显示与输入为毫米，内部存储为米（保留 3 位小数）。
- 坐标：平面 x 向右、z 向下，y 向上；与旧版和数据清洗规范一致。
- 铺位形态只关注三类：**边厅店、中岛店、专区**（渠道类型不建模）。
- 市场：国内 / 海外，默认国内；决定 Logo（国内“影石Insta360”，海外“Insta360”）。
- SI 风格：默认 SI1.0，可选 SI2.0（SI2.0 是现行标准，但生成方案以 SI1.0 为主）。

## 4. 空间输入

### 4.1 手动输入
在画布上绘制或输入多边形边界、入口、障碍物；也保留“长 × 宽”快速创建矩形。

### 4.2 上传简图识别（第二期）
- 格式：JPG / PNG / PDF（按页选取），上限 20MB；不支持 DWG。
- 识别方式可选：本地识别（OCR + 图像处理）、各大模型识别。**默认先本地识别，失败自动转大模型。** 失败判定：比例无法标定、边界不闭合，或整体置信度 < 0.6。
- 一张图有多个空间时由用户框选识别区域。
- 简图可能只有轮廓、一条边长、方框代表的软装、红色标注的新增需求、文字指令；识别需要区分**现状 / 新增需求 / 区域外环境**，并识别已有道具、对应到模型库。
- 比例来源：总尺寸、分段尺寸、带尺寸的道具名称（如“1.2米配件柜”）、模型库标准尺寸；都缺时由用户输入一个已知长度校准。
- 识别结果在页面上**重新绘制成带尺寸标注的平面**，用户确认或修改；随后可“生成软装布局”，也可直接在这张图上手动摆放。
- 识别不到的内容标为“待确认”，不猜测。

## 5. 自动排布

- 一次生成 4 个方案：**尽量多放、按面积推荐、尽量少放、参照相似门店**。用户选择其一后继续修改迭代。
- 支持异形空间。
- **规则分软硬**：硬约束只有“在边界内、不重叠、不压障碍物与入口”；通道宽度（指导值 1.2m）、道具间距（0.9m）、入口缓冲、靠墙边距等都是带权重的软约束，条件不允许时可让步，方案中注明让步项（例如“主通道让步为 1.0m”）。
- 没有必有道具。必选组合规则将根据 418 家门店清洗数据统计整理成可调整的规则表（例如面积过小只放边桌储物柜是可接受的）。SI 手册作为指导依据，不作为硬性要求。
- 道具只能刚体平移和旋转，**禁止镜像和拉伸**；尺寸以真实模型为准。
- 旧版“实验训练模型建议”（岭回归桌数）下线，待清洗数据出来后重新评估。

## 6. 白模与渲染

- 白模由布局数据确定性生成，不使用 AI。
- 生成白模后系统**默认自动生成 8 个视角图**；用户可以旋转查看白模、**在三维中直接拖拽修改软装**、自行选取渲染角度、增加或删除视角。
- 同一视角的白模图与材质图必须使用同一场景、同一相机、同样的物体显隐，只切换材质。
- 渲染：先在浏览器（Three.js）完成；第四期增加服务器 Blender 正式渲染。渲染结果保存到服务器，挂在项目历史下。
- 中岛店默认灰色地面，四周连续不锈钢包边。
- 灯箱与广告画面：允许联网找图，横屏配横图、竖屏配竖图，不拉伸；记录来源与授权状态。
- AI 增强效果图：可选功能，默认关闭；最终图以 3D 渲染为准，增强图只作参考。

## 7. 交付

沿用 Skill 的双 PDF 交付规则（`资源库/08-skill/.../references/双PDF交付规则.md`）：

- `00-影石xxx店完整方案.pdf`：带尺寸、图例和说明的平面页，效果图总览，每个材质视角的独立大图页，必要的白模与校核记录。
- `影石xxx店方案.pdf`：首页只放店名标题、平面图与图例；之后每页一张材质效果图；不含总览和白模。
- 目录：`门店名称_门店类型_面积_YYYY-MM-DD/`，内含 `01_平面图/`、`02_效果图/`、`03_总览/`、`04_源文件与记录/`；同名时追加 `_修订02` 等后缀。
- 第一期就生成双 PDF（使用浏览器渲染图），Blender 上线后可替换为正式图。
- 交付方式：网页下载 ZIP，**同时**写入服务器配置的归档目录。
- 另保留：平面 SVG/PNG、项目 JSON（兼容旧版 v2 格式导入）。

## 8. AI 能力

### 8.1 模型与切换
- 模型通过后端适配层调用，密钥只存在于后端环境变量。
- 设置中可分别为 **Agent** 与 **平面识别** 选择模型，当前**全站统一**，加入用户系统后改为每个用户各自选择。
- 首批：DeepSeek（deepseek-flash）、通义千问（qwen3-vl-plus / qwen3-vl-flash）、本地识别；本地视觉模型后续加入。
- 境外模型（如 Claude）代码预留，仅在配置了密钥并打开开关后出现；网络合规确认前默认隐藏。

### 8.2 预算
- Agent 与平面识别共用每日 50 元人民币预算，北京时间 0 点重置。
- 超额后停用 AI 功能；本地识别、规则排布等照常可用。
- 每次调用记录模型、token、费用；页面显示当日剩余额度。

### 8.3 Agent（第三期）
- 最大权限：修改空间与布局、生成方案、切换 SI 风格与市场、管理视角、触发渲染与导出、修正识别结果。
- Agent 只能调用程序工具，不直接计算坐标、不直接写数据；每次修改生成新的历史节点，**直接生效，可撤销**。
- Agent 会看当前平面截图来理解指令；用户在画面上选中的对象作为上下文。
- 对话与工具调用记录按项目长期保存，当前所有人可见。

## 9. 数据与历史

- 项目历史为节点树；历史节点不可变，在“树图”中可隐藏、可恢复。
- 项目软删除，可从回收站恢复。
- 多人同时编辑：后保存者收到冲突提示，选择覆盖或另存为分支。
- 浏览器中的旧项目可通过 JSON 导入迁移。
- 模型库、门店资料、SI 标准等目录数据只通过命令行导入，网页只读。
- 数据库与文件每天自动备份到本机另一块盘。

## 10. 数据清洗与模型资产（并行工作）

- 418 家门店 PDF 由另一窗口按[清洗规范](../资源库/06_生成流程文档/02_平面图与效果图提取.md)批量清洗，产出写入 `资源库/90_处理过程与审核/`。同一门店多份方案：最新为主版本，其余作为备选方案进入案例库。
- 38 件软装由另一台电脑从 SketchUp 2026 导出 DAE，再在本机转换为 GLB（米制、Y 向上、底部中心），逐件核对尺寸、正面朝向与材质。过渡期缺失模型用参数化占位体并明确标注。

## 11. 非功能要求

- 只适配桌面版 Chrome / Edge；界面仅中文。
- 所有主要代码使用 TypeScript 严格模式；每个 API 有输入校验、统一错误格式和安全限制。
- GitHub Actions 运行类型检查与测试。
- `tools/` 下的 Python、Ruby、SketchUp 工具原样保留，不纳入重构。
