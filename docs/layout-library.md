## 记录方式

采用 JSON 主数据 + 可筛选本地 HTML 表格，而非手工改文件夹名。每份PDF一个记录，保留原路径。

- `si`：SI1.0 / SI2.0 / null；保留总表原始值后再规范化。
- `shopType`：边厅店 / 中岛店 / 其他 / null；不把专卖店、体验店这些经营类型当作铺型。
- `combinedTag`：两项都确认才生成“SI1.0 中岛店”。
- `recordId`、`sourceUrl`、匹配方法、更新时间：追溯飞书依据。
- `filenameTypeHint`：文件名中的边厅/中岛提示，独立于正式标签。“边厅改中岛”记为中岛候选，但仍需核对版本。
- `planPages`、`constructionPages`、`imagePages`：文本规则定位的候选页号，不是人工确认结果。无文字页面可能是扫描图、效果图或空白，不能自动都归效果图。
- `status`：待总表匹配 / 名称歧义待核对 / 已匹配待图纸版本核对 / 已核验。

输出：`资源库/00_资源索引/历史目录/classification/stores.json`、`index.html`、`page-index/*.json`。

## 匹配总表的原则

优先精确名称匹配。第二步仅做空格、大小写、全半角等标准化；去掉“授权体验店”等后缀后的匹配只作为候选。保留城市、商场、楼层、二店、换址/扩铺等信息；同名多行、历史改造版本不能自动取第一行。

飞书的SI形象可能反映当前门店，PDF可能是旧版。正式使用前将PDF设计日期与总表版本核对。SI、铺型缺失时保留空值，不通过灰/黑色直接确诊。

## 是否切图用于训练

需要，但先做检索与规则提取用的配对样本库；目前不启动模型训练。平面图比效果图更直接提供坐标、尺寸、道具数与相对关系；效果图主要补充材质、造型与视觉标准。

1. 标签核验后，按SI1.0边厅、SI1.0中岛、SI2.0边厅、SI2.0中岛分层，每类优先挑3–5家完整门店；类内再覆盖不同面积、长宽比。
2. 每店保留原PDF、设计日期、原页码；切出带尺寸的家具定位图，另做纯布局裁切，不覆盖原件。
3. 选2–4张布局可对应的效果图。效果图视角与平面关联标注，不将同店不同方案混在一起。
4. 标注轮廓、入口、柱位、道具编号/尺寸/朝向/位置；把“明确标注”“尺寸链推导”“视觉估计”区分开。
5. 后续若训练，按门店/改造家族分训练、验证、测试；同门店不同页面、裁切、渲染角度不得跨集合。清除重复图，测试集不参与规则调参。
6. 先基于样本检索和约束规则生成四方案，用保留门店验证，再判断是否有足够高质量数据值得微调模型。418份PDF不等于418套完整、独立、同标准训练样本。
