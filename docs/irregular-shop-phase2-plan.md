# 异形店第二阶段：道具任意角度（方案草案，2026-10-15）

接 [异形店支持方案](irregular-shop-plan.md) 第 4 节第 7、8 项，以及 10-14 决议的第 1 题：道具支持任意角度，交互时吸附到墙的方向和 15° 档。本文给出改动范围、数据兼容方式、分批计划和待确认的问题，**确认后再动手**。开工时间排在系统测试师的墙面安装 #90 合并之后。

## 1. 现状

道具现在只能转 0°、90°、180°、270° 四档，占地一律按横平竖直的矩形计算。代码核查发现，依赖这个假设的地方分布在：

| 环节 | 大约处数 | 说明 |
|---|---|---|
| 数据定义 | 3 处，另有 2 个接口生成物 | 角度只允许四个值 |
| 共用几何计算 | shared 约 25 处，api 约 10 处，web 约 8 处 | 占地、碰撞、是否在店内、离墙距离、朝向、吸附 |
| 自动排布 | planner 约 10 处 | 只认横平竖直的墙，中岛桌只试横放、竖放两种 |
| 设计助理 | 约 6 处 | 斜墙取最接近的直角；提示词写明只能四档 |
| 平面图、三维 | 约 12 处 | 选中框、命中框、无模型时的占位盒都是横平竖直的 |
| 展陈、交付 | 约 5 处 | 展陈按长边判断横版、竖版；交付图例按尺寸去重 |
| 导入导出、识别 | 约 5 处 | 旧格式导入时，非 90° 倍数的角度一律改成 0°；识别结果吸到四档 |
| #90 的墙面安装 | 5 个函数 | 贴墙、重叠、离地高度判断都按四档和横平竖直的墙 |
| 测试 | 约 12 个文件 | 有断言“45° 会被拒绝” |

## 2. 数据怎么兼容

- **数据库不用迁移**：布局整体存成一个 JSON 字段。
- **角度**：从四个值放开为 0–360° 的任意数，保留一位小数。单位仍然是度，语义不变（展陈窗口已确认按最近的轴向处理）。
- **道具宽、深**：现在存的是“转过之后、横平竖直的占地尺寸”，转 90° 时宽和深会对调。任意角度下这种存法说不通，改为**存模型本身的宽和深，不随角度变化**。
  - 布局版本从 3 升为 4。读取第 3 版数据时自动换算：90°、270° 的道具把宽、深对调回来。旧项目、导出文件和草稿都能直接打开，结果与现在完全一致。
  - 下游凡是直接读宽、深的地方（展陈、图例、设计助理的空间描述）都要跟着改。统一通过 shared 里的一个函数取“占地多边形”或“外接矩形”，不再各自换算。
- **新增共用几何模块**：放在 `packages/shared/src/geometry/`，提供有方向矩形的角点、相交、是否在店内、间距、贴墙投影这几个函数。排布、设计助理、#90 的墙面安装和编辑器吸附都改用它。角度正好是四档时，结果与现在逐字节相同；这一点用架构评审时那套 9180 个配置的对比来验证。

## 3. 分批计划（每批一个 PR）

1. **数据与几何**（shared，界面不变）：放开角度定义，升布局版本并自动换算，加入共用几何模块；校验、#90 的墙面安装改用新模块；重新生成接口文件。验证：四档数据前后完全一致，并新增斜放道具的碰撞和越界测试。
2. **编辑器**（web）：
   - 平面图和三维按任意角度画道具，选中框、命中框、占位盒都跟着转；
   - 属性面板加角度输入框，保留 ±90° 按钮；
   - 平面图上加旋转手柄，拖动时吸附 15° 档，靠近墙时吸附到墙的方向；
   - 靠墙一侧的角点吸附到斜墙上（原方案第 8 项）。
   
   验证：浏览器逐步操作截图；四档项目的截图前后逐像素相同。
3. **自动排布贴斜墙**（shared planner）：墙不再限于横平竖直，斜墙、折线弧墙上每段够长就沿墙放柜子，柜子跟随该段的方向。验证：9180 个配置里矩形店结果不变；梯形、弧形和真实样例的斜墙边有道具，截图对比。
4. **设计助理、导入与识别**（api）：
   - 助理贴墙时沿真实墙边的角度放，提示词和参数同步修改；
   - 旧格式导入保留原角度；
   - 识别结果偏差 3° 以内吸到四档，超过的保留原角度；
   - SI 切换时，新道具沿用原角度。
5. **展陈与交付对齐**（与展陈窗口约时间后做）：展陈按最近轴向判断横版、竖版，展陈窗口已同意；交付图例改为按模型去重。这一批会碰 `deliveries` 和 `displays`，要先和展陈窗口商量好由谁来改。

第 1 批是基础，后面四批依赖它。第 2–4 批互不依赖，可以并行。

## 4. 风险

- **宽、深语义改变**是最大的风险。所有读宽、深的地方都要改。第 1 批会把这些地方集中到一个函数，并为每处补测试，避免漏改造成斜放道具的尺寸算错。
- **排布变慢**：有方向矩形的碰撞比轴对齐矩形慢。排布只在需要时（斜墙边）使用新算法，矩形店仍走原路径；若明显变慢，会在 PR 中说明实测时间。
- **#90 的墙面安装**：它的 5 个函数在第 1 批里一起改。改之前通知系统测试师，避免它同时在改。

## 5. 需要确认的问题（未回答的按推荐执行）

1. **中岛桌要不要跟着斜墙转**
   - **A（推荐）**：中岛桌仍按主入口方向整齐排列，只有靠墙的柜子贴斜墙。店内动线整齐，展陈的横版、竖版也好判断。
   - B：靠近斜墙的中岛桌也转成与斜墙平行。
2. **弧形店面（多段折线）上要不要放柜子**
   - **A（推荐）**：每一段够长就放，柜子跟随该段方向；段太短就不放。
   - B：弧墙一律不放，只放直墙。
3. **识别出的斜角怎么处理**
   - **A（推荐）**：与四档相差 3° 以内的当作直角，超过的保留识别出的角度。
   - B：全部吸到四档，斜放由人工调整。
4. **编辑器的角度吸附**（原方案已定为吸附到墙方向和 15° 档，这里确认细节）
   - **A（推荐）**：拖动旋转手柄时默认吸附，按住 Alt 键可以自由旋转；属性面板可以直接输入任意角度。
   - B：只吸附，不允许 15° 档以外的角度。
5. **上线顺序**
   - **A（推荐）**：第 1、2 批先上，人工可以斜放道具；第 3、4 批随后跟上，让自动排布和设计助理也能贴斜墙。
   - B：五批全部完成后一起上线。
