# 渲染背景编辑验收清单

验收工作区使用 `codex/render-background-qa-20261110`、API 3073、网页 5253、独立 PGlite 和外置文件目录。基线为 `47778b7a`，本轮占用由主开发在 `e35e510d` 统一登记。以下为计划，所有功能用例待集成候选实测。

## 样本与比对

准备同一渲染节点的 A、B 两个视角，以及另一个节点的同名 A 视角。准备一组升级前已保存材质渲染的视角和一组新建视角。两张合成背景使用不同尺寸、明显不对称的四色角标、横竖刻度和一条穿过 3D 物体轮廓的色带。用这些标记判断坐标方向、旋转中心、遮罩边界、跨视角串图和导出位置。主库和真实门店素材不参与测试。

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| BG01 | 打开升级前节点，切换已有材质图和无图视角，重载后下载渲染 ZIP | 无背景状态可以读取。旧材质图与原始图片像素一致，既有下载路径可用 |
| BG02 | 分别拖放与选择文件。替换 A 的背景，再切换 B 和另一节点的 A | 每视角只保留一张有效背景，另外两个视角各自保持原配置。取消选文件或上传失败时原视角仍可用 |
| BG03 | 输入精确尺寸、位置、缩放和角度，拖动后切换视口尺寸并重载 | 宽度为单一尺度，高度按原图比例计算。角标方向、位置及保存值与预览一致。补测接近水平的视角，确认编辑预览和成图的视线一致 |
| BG04 | 在空视角首次进入编辑，先取消选图，再成功加图。手动恢复半透明墙，切视角、退出再进入并重载 | 成功添加新背景时默认隐藏半透明墙。打开编辑或取消选图保留已有视角状态，手动设置按视角保存 |
| BG05 | 点出闭合遮罩穿过 3D 物体，再移动顶点、删除、移动和旋转背景 | 闭合后区域露出相同位置的原照片并盖住 3D。顶点随照片变换。删除后 3D 恢复。未闭合或退化路径不能改变最终图 |
| BG06 | 添加辅助线，拖动和缩放照片，显隐、删除、重载 | 辅助线在照片坐标中，随照片变换且可恢复显隐。最终渲染无辅助线、控制点或编辑框 |
| BG07 | 分别撤销替换、精确输入、移动、缩放、旋转、遮罩和辅助线操作，并切换视角后再撤销 | 一次完整拖动只需一次 Ctrl+Z。撤销恢复相应视角及动作前状态，连续动作按序回退。输入框中的文本撤销不被全局快捷键抢占 |
| BG08 | 两标签打开同一视角，用同一个 `expectedBackgroundRevision` 保存不同内容。模拟慢上传时切换视角，网络失败后重试 | 首个有效保存推进版本，第二个旧版本保存返回 409。迟到响应不会写入错误视角或覆盖较新的状态，冲突后可恢复编辑 |
| BG09 | 保存材质图后单独修改背景、遮罩或墙显示，再导出。然后只改辅助线 | 影响最终像素的编辑后不会误交付旧图。辅助线变化不会改变输出像素。是否重渲染及状态提示以冻结契约为准 |
| BG10 | 生成最终图和正式交付 ZIP，提取效果图、PDF 中的对应页与选配的展陈 PPT | 与同视角最终材质图比对颜色和关键位置。ZIP 中原图按像素比对，PDF/PPT 如重采样则比对可见区域及桌号。遮罩正确覆盖，辅助线不出现 |
| BG11 | 传入损坏或超限图片、跨节点或视角 ID、已失效的渲染与编辑版本 | 清楚拒绝无效数据。旧视角、现有图片及其他视角记录保持一致 |
| BG12 | 拦住 A 在背景版本 R 下生成的材质图上传，更新背景至 R+1，再放行旧上传。随后按 R+1 重渲染 | 旧上传返回 409，不会成为当前图或进入新交付。R+1 的成图和归档可读取。同样检查从无背景到有背景、移除背景与撤销恢复 |

## 接口审查项

- 冻结口径采用等比缩放，`transform.width` 为唯一尺度。成功添加新背景时默认隐藏半透明墙，打开已有背景尊重保存值。
- 现有渲染以节点和视角 ID 定位，另有场景与视角签名用于判旧。建议新增独立的背景像素版本，覆盖替换、变换、遮罩和影响渲染的墙设置，将辅助线和选中态留在编辑状态。旧记录缺背景状态时应继续与旧签名兼容。
- 保存材质图时，应校验客户端合成所用的背景版本与当前版本。慢请求跨视角返回时应绑定请求发起时的节点和视角。背景图片引用与状态保存需要明确失败、重试和冲突行为。
- 照片坐标的单位、原点、旋转中心、缩放及裁切顺序应在契约固定。画布预览、最终输出和遮罩取样均用同一坐标定义。EXIF 方向按解码后的照片尺寸处理。
- 渲染 ZIP、交付和展陈都从当前材质图读取。现有交付会拒绝缺失或过期渲染，展陈会筛除过期材质图。测试需要覆盖三个消费者，防止新背景只在编辑预览中出现。

## 记录口径

每条记录候选提交、节点与视角、输入尺寸、复现步骤、预期、实际、结论和截图或导出路径。PNG 在无重采样区域比对像素，压缩重采样的文件对比色块与轮廓。旧视角兼容、跨视角串图、保存版本冲突和最终交付不一致均作为发布阻塞项。单元或 API 检查与浏览器验收分别记录。

基线 `47778b7a` 的 `renders.test.ts`、`deliveries.test.ts`、`display-api.test.ts` 在隔离内存数据库中共 12 项通过。该结果只覆盖现有渲染和导出行为。

核心 `02392dd2` 已静态审查。独立 Fastify/PGlite 实测同一修订并发保存返回 200 和 409，背景变更后的旧修订材质图上传返回 409，已有材质图在仅切换辅助线显隐后仍有效。旧无背景视角不带修订号上传返回 201，JPEG 上传返回规范化尺寸 450×720。同项目文件可显式复用到另一视角，跨项目绑定受服务端归属校验。上述结果不包含编辑 UI、成图和交付的组合验收。

发现一项并发读取缺陷。同项目重复上传相同图片会以项目 ID 和规范化图片 SHA 命中同一存储路径，再以普通写入打开已存在文件。隔离复现让第二个视角的上传停在截断之后、写入之前。原图片 GET 从 200/8127 字节变成 200/0 字节，已有视角可能解码失败。建议同内容命中时复用已校验的文件，或先写同目录临时文件再原子发布。回归应确保重复上传期间已有图片始终完整可读。

主开发添加原子发布后已隔离复测。第二个视角复用同一图片时，原图 GET 在上传暂停前后均为 8127 字节，内容逐字节相同，两个请求得到同一文件 ID。两个首次上传暂停在临时文件打开时，正式路径仍不存在。模拟 Windows 下第二个发布请求重命名返回 EPERM 后，两个上传均返回 201，正式文件 SHA 正确，临时文件清理完毕。测试使用显式同步屏障控制顺序，EPERM 为模拟故障。
