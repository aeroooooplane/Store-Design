# BoldSite 上云部署

## 平台要求

以下约束来自平台示例和用户转来的部署说明。示例的代理与重启测试是在本地运行，平台上的实际行为以试点验收为准。

- 平台分配 `/svc/{appId}/`。网页与 FastAPI 同目录、同进程发布，入口为根目录的 `index.html`。将构建目录中的文件放到发布根目录。
- `boldsite.json` 使用 `type: service`、`runtime: python3`、`startCommand: python3 app.py`、`port: 9000`。进程监听 `0.0.0.0`，端口读 `CAPort`，持久路径读 `DATA_DIR`。
- 工作台前端的云端构建命令是 `pnpm --filter @store/web build --mode boldsite`。Vite 使用相对 base 和 `static/`。平台保留的 `assets/` 与构建产物分开。
- 云端使用 Hash 路由，例如 `/svc/abc/#/projects/123`。客户端由入口路径推导服务前缀。云端 API 请求和旧接口返回的模型、照片、下载链接均保留该前缀。
- 发布入口保留尾部斜杠。若平台接受无尾斜杠的入口，代理或服务需将其重定向到 `/svc/{appId}/`，供浏览器正确解析相对静态路径。
- FastAPI 继续沿用工作台现有的 `/api/v1` 数据契约。服务端兼容代理剥前缀、透传前缀和 ASGI `root_path` 的情况。静态服务还要明确提供构建产物中的根目录图标和 `manifest.webmanifest`。
- 预览区由静态前端保留导航并提示「预览模式，部署后数据可用」。当前置健康检查失败时，业务页不发业务请求。诊断示例有独立的健康响应和 CRUD 字段，用它自己的 `index.html` 验证平台。

## 第一次平台验收

1. 用独立测试部署和虚构数据运行诊断示例，核对页面解析出的 API 前缀、健康检查、项目新增与编辑、上传与下载。
2. 重启或重新部署后核对实例 ID、项目和上传文件。按实际部署链接复测两种 URL 入口。
3. 在预览区打开工作台构建产物，确认 API 断开时有提示并可继续浏览导航。正式接入工作台契约后，复测嵌套路由刷新、模型和展陈图片、上传与下载。
4. 确认应用仅指定公司成员可见并核对上架设置，再接入真实门店图纸。

## 待确认与取舍

| 问题 | 需要的确认 |
| --- | --- |
| Python 及代理 | Python 版本、环境变量与密钥入口、实际是否剥前缀、预览和正式环境的差异 |
| 数据库与持久盘 | PostgreSQL、对象存储是否可用，应用能否固定为单实例，`DATA_DIR` 的配额与备份恢复方式 |
| 运行配额 | 部署包和上传体积、内存、请求超时、后台进程及实例回收限制 |
| 访问与发版 | 公司账号、指定成员、身份传递、应用广场可见性、测试环境与回滚 |

SQLite 仅作为受控试点方案。NFS 上关闭 WAL 后，仍需依赖文件锁和同步语义。正式多实例写入优先采用 PostgreSQL。识别与交付应先返回任务 ID，任务状态持久化，领取机制防止重复执行。API 密钥通过平台认可的秘密存储注入。

代码、资源和数据库迁移版本随发布记录。现有 Windows 工作台继续作为迁移核对基线，生产数据先用项目导出、导入验证。
