# 原图直入本地试验（2026-11-12）

## 结论

已打通「未预先人工标注的图片 → 本地轮廓候选 / 整页 OCR → 原生项目 → 修改层高、保存刷新、三维」试验链路。三张独立原图自动完整可用 **0/3**，不能宣布无标注自动识图已完成，也不接管主工作台生产识别入口。入口、柱位、内部墙体与家具尚未可靠识别。

此前 #213 的样例复用了描点。本轮只给识别器位图，不给 PDF 矢量、文本层、已有描点、审核包或真实几何答案。图纸本身仍有设计尺寸和文字；这不等于证明完全无尺寸文字的图也能恢复真实米数。

## 分支、实现与数据边界

- 基线 `ef817254`，分支 `codex/raw-plan-20261112`；原 `feat/recognition-openings` / 草稿 #156 保留。未在主工作区切分支或提交。
- 新增 `tools/recognition/raw-*` 独立工具、本文及 CI 专项；不改 Workbench、PlanView、editor-state、white-scene、deliveries、PlanEditor、共用 schema、依赖或数据库迁移。
- 现有生产本地路径只接受矢量 PDF，不能直接完成图片识别。本试验单独提供本机上传页，不把它标成生产功能上线。
- 使用保留的 11-09 ONNX，SHA256 `cfdcfc0c325b7d7389d316a3630bec64630f58b6ddea163a6f2732791798bda4`。不训练、不替换权重、不重新调阈值；固定 256 像素、阈值 0.5、原极性归一化。
- 主平面整页渲染为 2200×1556 图片，再做轮廓推理及本地 PP-OCRv4。像素连通外环、孔洞及原概率保存，不取凸包、不静默只保留最大连通块。小于 4 模型像素的外环过滤数量记录在原始输出中；闭环简化容差固定为 1 模型像素。
- 轴向墨线只供尺寸候选，不当成墙体标签。尺寸至少有两个不同长度读数支持同一比例，竞争尺度时留空；仍为未核实候选。层高只从明确室内文字读取，公区、门头、设备和平方米误读不能补层高。
- 用户选择门店类型和比例，必要时点选一个已知长度；缺少比例或层高阻断导出。导出只是所选外轮廓，未知入口和障碍在原生格式中为空占位，侧车来源文件明确未知。三维因此是封闭壳体，不能当成真实无入口门店。
- 预测孔洞不能进入当前外轮廓预览格式；默认阻断，只有单独明确允许省略后才能导出。孔洞数量 / 坐标及原始预测仍保留，绝不把省略后的候选算自动完整成功。多个候选需选择一个，不自动合成多空间。
- 透明图先铺白；上传限长边 4000 像素、12M 像素及 20MB。只监听 127.0.0.1，校验 Host、Origin 和主动操作头；无云端路由、模型下载或外部脚本。

## 三张诊断样本

选择前先按编号、来源 SHA、规范化门店名及别名排除 45 家验收、48 家开发和既有训练 / 内部验证来源。按固定种子排序选 1 家中岛、2 家边厅，在看到模型输出前冻结清单及原图 SHA。这里只检查了身份元数据，不读这些排除集合的图像、标签或评分。此排重不能证明所有未知近重复都已排除，三张样本也不代表全体门店成功率。

| 来源                     | 页码 / 类型 | 首轮输出           | 实际问题                                                       | 修订后的语义候选                                    |
| ------------------------ | ----------- | ------------------ | -------------------------------------------------------------- | --------------------------------------------------- |
| PDF-106 合肥新粮仓       | 10 / 中岛   | 1 区域、163 条 OCR | 设备尺寸表、外侧标识及入口箭头附近区域被连进门店；多入口未识别 | 不给比例；2850mm 高度来自“按标准设置”，不是实测确认 |
| PDF-222 武昌万象城       | 10 / 边厅   | 3 区域、124 条 OCR | 主边界粗糙，另外两块尺寸文字误检；柱位、后场隔墙和入口缺失     | 9.6884mm/像素、3300mm，高度/比例均未确认            |
| PDF-226 武汉婚纱摄影照材 | 6 / 边厅    | 1 区域、106 条 OCR | 库房和上边界判错、前侧外溢；原文 3m 被读为 3㎡                 | 14.2185mm/像素；层高留空，不能拿公区 3.09m 替代     |

三张都不是自动完整门店。未计算 IoU，未人工修好几何后计入成功。旧诊断比例在中岛上约为 1.1873mm/像素，明显不对；新增尺寸一致性规则拒绝它。首轮 `raw.json`、`reading.json` 在视觉检查前冻结；候选规则是在看见失败后修订，故 v2 语义结果属于开发迭代，**不是独立盲测成绩**。

## 验证与限制

- 7 项 Node 专项：比例、层高、未知字段、量尺、几何、门店类型、孔洞省略保护；进入 CI。
- 6 项 Python 专项：透明背景、凹形轮廓、分离区域、孔洞、对角像素和矩形；本机通过，CI 未安装模型运行环境，故不宣称 CI 跑过 Python / ONNX。
- 全仓 801 项测试通过（shared 256 / web 328 / database 7 / api 210）；lint、typecheck、format 检查通过。
- 实际 Chrome 上传原图，候选导出、工作台导入 201 零警告、实际三维、层高 3300→3500mm、保存刷新和原候选保留；390px 无横向溢出、无脚本错误 / 外部浏览器请求。导出前确认类型、比例、不完整结果及孔洞省略，这些是人工操作，不称自动完成。
- 首次真实上传约 8.83 秒；在并行测试负载下另一次约 34.4 秒，不提供稳定延迟承诺。最终复跑耗时见外置页面记录。API 本地推理、OCR 和渲染的硬件负载未做性能基准。
- 三维显示不该有的折线墙，直接暴露低分辨率轮廓误差。OCR 读到数字不代表找对尺寸线，仍可能读错 / 配错。黑底、扫描失真、照片透视、无文字尺寸输入还未通过本轮完整验证。
- 没有用 48 家重新算开发分数：本轮是新输入端到端诊断，原始质量仍不达标；下一条识别路线固定后再用 48 家复评。45 家继续只做最终验收。
