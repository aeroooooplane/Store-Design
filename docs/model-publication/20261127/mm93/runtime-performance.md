## 加载方式

- GLB 获取与解码合计最多并行两项；相同 URL 共用一个 Promise，排队状态也去重，失败释放槽位并允许重试。
- 同一模型多个实例共享几何、贴图与场景材质副本，移除后重加不重下资源。
- 已预处理的材质版不在 UI 线程遍历五十万面来寻找 SketchUp 背层。
- 三张原贴图逐帧预热，随后预编译，模型准备完毕再进入场景。普通模型不进入该贴图预热分支。

## 浏览器测试

采用实际 WhiteScene，4×3 m 虚构空间，1000×720 视口，Edge 无头硬件 WebGL；Intel Graphics / Direct3D11，支持并行着色器编译。所有资源来自隔离 5268 端口，正式项目、接口及资源库零写入。

初轮对照（主线接线前的独立 helper 试验）：

| 项目 | 原件直接加载 | 无损材质＋白模 | 再加逐帧预热 |
| --- | ---: | ---: | ---: |
| 白模首次就绪 | 805 ms | 119 ms | 73 ms |
| 材质首次就绪 | 1,244 ms | 982 ms | 500 ms |
| 材质阶段最长长任务 | 331 ms | 375 ms | 78 ms |
| 单辆旋转 | 约 61 fps | 约 61 fps | 约 61 fps |
| 四辆旋转 | 约 38 fps | 约 60 fps | 约 59 fps |

已定位原版集中停顿来自三次 texSubImage2D 上传。分帧后上传没有集中到一次首次 render，材质就绪时间包含异步下载、解码、上传与预编译。数值有运行波动，不将缓存命中或四辆数据外推至所有设备。

合入地面 #314 和 X6 #316（c1f15a82）后，未接线时再次复现了 205 ms 集中上传。文件释放后仅在 WhiteScene.prepare 接入 helper，新增关闭视图时取消上传的保护。正式调用路径复测结果见 [浏览器回执](runtime-browser-validation.json)：白模 47 ms，材质 565 ms，最长单次任务 81 ms，四辆重复添加 32 ms，单/四辆旋转约 60 fps，移除后重加 32 ms。真实“选择模型→准备→点击放置”路径只先加载材质，准备 450 ms，随后放置 32 ms 且无长任务；切白模后才请求白模文件。材质与白模 800×600 PNG 导出均人工看图通过。强制丢失并恢复 WebGL 上下文后，地砖采样像素前后同为 RGBA(186,184,183,255)，页面无错误。X6 正常模型选取 256 ms、放置 19 ms，放置无长任务；使用未标记材质，继续走原有规则。

[运行资源回执](runtime-resource-validation.json) 包含原件及两种运行模型的哈希、字节数、面数、尺寸漂移、图片哈希和保真断言。

核对白模只请求 white.glb，材质再请求 finish.glb；四次放置、全部移除及重加，合计仍仅两个模型请求。四辆共用一个材质几何、三张贴图，GPU 纹理数量与一辆一致。页面错误和外部网络请求均为零。截图人工复核原红色车身与图案正常，照明使用工作台环境。

## 限制

保留三张 4K 图片意味着 GPU 占用仍然存在：完整 RGBA8 mipmap 约 256 MiB（估算，不含几何及工作台其余资源）。逐帧上传降低集中停顿，但该机单张上传仍可能约 60–90 ms；不能承诺任意硬件和数量绝无短暂停顿。未采用有损降图、重绘或减面。网速慢时加载会等待，现有场景继续显示。

这是隔离运行候选，尚未分配正式目录 ID 或发布共享模型资源。原文件数值长度为 1，实际毫米尺寸仍待入库标定。正式发布继续按资源负责人流程核对尺寸、朝向、五向图、manifest、资源锁以及 catalog:white / catalog:finish / catalog:import。
