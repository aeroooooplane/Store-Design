# 另一台电脑：首次导出一张真实体验桌

此工具包用于文件交接，无需配置远程桌面或网络服务。脚本尚未在真实 SketchUp 内验证；先完成一个道具，不批量导出。

## 1. 拷贝并准备

把本工具包解压到一个有写入权限的文件夹，例如桌面的 `Insta360-SU`。另行拷贝 `影石通用模型.skp`（约 1.08 GiB）；工具包不包含这个大文件，也不需要全部 PDF。

在 SketchUp 打开原模型。源文件头版本是 26.1.189，能否正常打开以这台电脑的实际结果为准。若提示需要修复、丢失内容或不兼容，先记录提示，不要覆盖原文件。若需整理组件，只操作另存的工作副本。

## 2. 加载导出脚本

打开 SketchUp 的 Ruby 控制台（Ruby Console，在菜单中寻找；位置因版本和语言而异）。粘贴以下一行，弹出文件选择窗口后选择工具包里的 `export_selected.rb`：

```ruby
p = UI.openpanel('Select export_selected.rb', '', 'Ruby Files|*.rb||'); load(p) if p
```

看到 `Ready: InstaAssetExport.inventory ...` 后，运行：

```ruby
InstaAssetExport.inventory
```

组件清单生成到脚本旁边的 `exports` 文件夹。清单包含零件、嵌套组件和可能未使用的定义；由我们继续整理，不需要你逐条命名。

## 3. 只选一张完整体验桌

退出所有组件编辑状态，在模型根层单击一张完整体验桌。只选择一个组或组件，确认选择框包含桌面、底座或桌腿，且不包含相邻道具和整间店。记录你知道的桌子尺寸、正面方向、SI 版本；不知道就写“未知”。

若桌子在一个包含多件道具的大组里面，不要把大组直接导出；请在工作副本中把完整桌子整理到根层。不要炸开原文件中的所有组件。

执行：

```ruby
InstaAssetExport.export_selected
```

成功后得到 `exports/selected-日期时间/`，含 `prop.skp`、`prop.dae`、`metadata.json`，有贴图时还应包含导出的贴图文件或子目录。保留整个目录结构，不要只拷贝 DAE。

如报错，保留控制台完整错误文本和已有输出；当前输出可能不完整，不要当作成功。脚本不主动保存或修改源模型。

## 4. 把结果带回来

将以下内容放入本项目的 `素材库/04_assets/incoming/`（没有则创建）：

- 完整的 `selected-日期时间` 文件夹；可先压缩再拷贝。
- `component-inventory-...json` 清单。
- 一张 SU 内显示选中道具的截图，作为外观核对依据。
- SketchUp 版本、显卡型号、显存，以及道具已知尺寸 / SI / 正面说明。

然后告诉我“导出结果已放入 incoming”。我会检查模型层级、贴图、单位和尺寸，转换为网页模型，再替换白膜中的占位道具。不按旧占位盒强行拉伸真实道具。

## 5. 后续显卡怎么用

第一阶段先导出资产；这一步关键是 SU 读取能力与内存，不必先配置 AI 训练。

第二阶段使用真实网格生成同一场景的白膜与八视角材质渲染。建议评估 Blender/Cycles，具体 GPU 后端取决于操作系统、显卡和驱动；有显卡不等于所有渲染后端都支持。

第三阶段如仍需要风格训练，再按显存确定方案，不先承诺这台机器能完成正式训练。不要继续把 tiny LoRA 流程验证当成可用的效果图模型。

## 可选：Windows 硬件报告

在工具包目录打开 PowerShell，执行 `& './collect-hardware.ps1'`。如被执行策略拦截，不必改系统策略；直接在任务管理器的“性能 → GPU”查看型号和“专用 GPU 内存”，在 SU 的“关于”页面查看版本。

报告只写到工具包本地，不自动上传。NVIDIA 显存尝试通过 nvidia-smi 读取；其他显卡请手动查看，避免把 Windows 通用字段的截断值当作真实显存。
