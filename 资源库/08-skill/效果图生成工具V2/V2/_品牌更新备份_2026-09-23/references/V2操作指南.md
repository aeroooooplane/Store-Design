# 规则V2：统一入口

## 环境和范围

保留 V1；V2 是完整独立分享包，复制整个目录即可保留原始 SU、两份 PDF、12 类缓存和西安示例。原始资产未修改；本次不是新一轮 SI2 校准或任意平面图自动建模。

环境：Blender 4.5.13、Python 3.12。直接渲染仍可只用 Blender；统一入口的解析需要 pdfplumber，预览拼图需要 Pillow。已验证版本在 scripts/requirements.txt；接收者可用自己的 Python 安装这些小型依赖。没有捆绑运行环境、OCR、BlenderProc 或 GPU 插件，没有外传素材。

原始 SU 只供新增型号入库，常规不加载；旧 delivery 文件夹为历史交付，路径对应见其中阅读说明。

## 最短操作

在 Codex 中可直接说：

“使用规则V2，先检查资料和环境，再生成四向预览与俯视总览；确认之后正式出图。复用缓存，只给我进度摘要。”

直接执行示例（替换自己的 Blender/Python 路径；下例 E:/门店工具 为分享包根目录）：

```powershell
& 'E:\门店工具\门店出图.ps1' -Action check -BlenderPath 'C:\软件\Blender\blender.exe' -PythonPath 'C:\软件\Python\python.exe' -OutDir 'E:\门店项目\环境检查'
& 'E:\门店工具\门店出图.ps1' -Action preview -BlenderPath 'C:\软件\Blender\blender.exe' -PythonPath 'C:\软件\Python\python.exe' -OutDir 'E:\门店项目\预览'
```

默认 job 为已确认的西安示例。preview 选前/后/左/右/俯视，输出 5 张材质、4 张白模和 `preview-contact.jpg`，不是所有十视角的正式图。600×400/8 采样，只检查布局。新项目必须传自己的 `-Job`，并按真实入口方向设定 job.view_groups.preview，不能套西安布局。

preview 成功后查看 `preview-contact.jpg`、对应白模、道具及遮挡关系。确认后将 Action 改为 render，使用新的 OutDir“正式版”：默认输出 1800×1200、10 材质+10 白模+1 俯视。画质参数与 V1 一致，批次改为先材质后白模，减少切换；不保证每台电脑更快。

## 六个操作

| Action | 输入 | 行为 |
|---|---|---|
| check | BlenderPath，必要时 Job | 打开场景，检查纹理、指定相机及标记家具的变换；不渲染。不是完整平面布局验收。 |
| parse | Source PDF、Pages、OutDir | 只解析明确页码，生成缓存 JSON；Pages 如 `1,3`，从 1 起。 |
| preview | BlenderPath、OutDir | 读取 job 的 preview 分组，低清批量并拼总览。 |
| render | BlenderPath、OutDir | 默认全量正式渲染，仍需先人工确认布局。 |
| supplement | BlenderPath、Views、OutDir | 必须明确视角 ID，仅补这些图；默认正式画质。 |
| status | 与运行时相同的 OutDir | 读取当前状态、总数、已完成、缓存跳过、当前图片耗时。 |

所有操作均可用 `-PythonPath` 指定 Python；依赖已经可用则无需安装。`-Profile draft/final` 可覆盖预设，例如先低清测试补图。Blender 默认 CPU/4 线程；直接 Python 入口可用 `--threads` 调整。

## 图纸缓存

```powershell
& 'E:\门店工具\门店出图.ps1' -Action parse -Source 'E:\门店项目\平面图.pdf' -Pages '1' -PythonPath 'C:\软件\Python\python.exe' -OutDir 'E:\门店项目\解析'
```

按源文件内容哈希、解析脚本版本、pdfplumber 版本和页码缓存。每次需读取所选源 PDF 字节进行哈希，但不重新解析命中的页面，也不读取别的 PDF/设计手册。新增指定页只解析新增页。缓存生成过程与精确米制校准分开：JSON 保留 PDF 点、X 右/Y 下、文本、词坐标和矢量线条。空文本只标记需要视觉/OCR 复核，不自动安装 OCR，也不凭空推断尺寸。修改 PDF 后自然产生新缓存。

只需给 AI 小型摘要和相关页，不把完整几何/手册全部送进对话。后续仍须核对尺寸基准、图纸标高、型号、边界和原模型朝向。194MB 手册不应随每个任务全部解析。

## 续跑与恢复

相同 job/场景/画质/视角再次执行，哈希有效的图片自动跳过。渲染先写 `.partial.png`，成功后提交最终 PNG，再记账；由系统锁阻止两个进程同时写同一出图目录。

中断后确认原任务已结束，在原命令上加 `-RecoverIncomplete`：渲染前先写对应 `.intent.json` 配置记录，恢复时用它或完成清单确认归属。同配置但未记账/损坏的图片、残留 partial 会移入所在图片目录 `_recovered` 下唯一命名的备份，再补渲染。没有任何归属记录的旧文件停止处理，需人工检查并备份。已有有效图片不动。**场景、相机、参数或脚本版本变了，必须新建输出目录**；恢复开关不会覆盖不同版本成品。V1 成品可以直接保留，不因升级重渲染；V1 缓存记录不能冒充 V2 缓存。

新增相机放入 job.views，ID 不重复。使用 `-Action supplement -Views '12_new_left,13_new_back'`；只渲染新相机，不需要重新解析图纸/重建场景。新相机位置在外部配置修改，不改冻结 scene.blend；参照运行与增量渲染文档的相机格式。

## 状态和日志

在另一个终端执行 Action status 并给出相同 OutDir。`progress.json` 在每个任务开始/缓存跳过/完成时更新；`controller.json` 记录子进程心跳。status 根据时间计算当前图耗时，心跳超过 60 秒提示检查进程，不虚构 ETA 或样本进度。硬终止可能保留 running 状态，不能只凭该字样认为仍在计算。

完整日志存放本次出图目录的独立 blender-*.log，正常只看 JSON 摘要；报错时才读取相关日志尾部。`last-run.json` 是最近一次成功运行，不应当作失败轮次的状态；以 progress 和当前日志为准。

## 边界

V2 没有改变门店尺寸或道具模型；没有自动解决立面缺失、SI2 标准缺失、未知型号。单元测试、低清实测与原模型文件哈希用于验证本次改动，不代表所有门店/设备均已验证。各脚本 --help 提供完整参数，旧 Blender 直接调用接口继续可用。

## 完成后的交付归档

渲染工作目录与最终交付目录分开。按照 `../SKILL.md` 的“交付与边界”，把已完成的平面和全部正式效果图合成一份 PDF，再连同原始单图和记录归档到命名文件夹；当前输出根目录为 `D:\Codex生成效果图\输出方案`。已有工作目录可直接复用，不因归档重渲染。

这是 Codex 完成方案时的交付步骤，当前六个命令本身不自动合册或归档；单独运行 render 成功不等于交付已完成。分享至另一台电脑后确认输出根目录即可，不改输入资料的相对路径。
